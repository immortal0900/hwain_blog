### 각각의 존재 이유와 쓰임새

1. **HTML이 필요한 이유:** 브라우저에게 "이것은 제목이다", "이것은 본문이다"라는 논리적 정보를 전달하기 위해서입니다. 이게 없으면 화면에 아무것도 나타나지 않습니다.
    
2. **CSS가 필요한 이유:** 사용자 경험(UX)을 높이기 위해서입니다. 버튼이 버튼처럼 보여야 사용자가 클릭할 마음이 생기기 때문입니다. **나중에** 브랜드의 색상 정체성을 유지하는 데 핵심적인 역할을 합니다.
    
3. **JavaScript가 필요한 이유:** 정적인 문서를 '애플리케이션'으로 바꾸기 위해서입니다. 데이터를 서버에서 가져오거나, 화면 전환 없이 내용을 바꾸는 등의 **동적 제어**는 모두 여기서 일어납니다.

### 왜 '동작(JS)'이 아니라 '디자인(CSS)' 영역인가요?

반응형 웹은 '논리적인 연산'보다는 **'시각적 배치 규칙'**에 가깝기 때문입니다.

- **HTML:** 콘텐츠(글자, 그림)를 준비합니다.
    
- **CSS:** "너비가 좁으면 그림을 아래로 보내고, 넓으면 옆으로 보내라"는 **규칙**을 정합니다.
    
- **브라우저:** 이 규칙을 읽고 화면 크기가 변할 때마다 즉시 다시 그립니다.
    

만약 버튼을 눌렀을 때 메뉴가 튀어나오는 것은 **JavaScript**의 영역이지만, 화면이 커졌을 때 메뉴가 상단에 펼쳐져 있는 것은 **CSS**의 영역입니다.


이 반응형 기술은 **'원 소스 멀티 유즈(One Source Multi Use)'** 전략에 쓰입니다. 모바일 앱용 웹페이지를 따로 만들지 않고, 하나의 HTML 파일만으로 모든 기기에 대응할 때 사용됩니다. 구글 검색 엔진 최적화(SEO)에서도 반응형 웹은 매우 중요한 평가 점수입니다.
