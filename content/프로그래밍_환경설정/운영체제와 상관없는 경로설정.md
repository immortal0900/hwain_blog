# #경로/apthlib
네, 가장 권장되는 **`pathlib`** 라이브러리를 사용하여, **프로젝트 최상위 경로(Root)**를 기준으로 깊이별 파일 경로를 설정하는 코드를 작성해 보겠습니다.

이 코드는 **어떤 폴더 구조에서 실행하더라도** 항상 올바른 파일을 찾아가도록 설계되었습니다.

### 📂 가정하는 폴더 구조

코드를 이해하기 쉽도록 아래와 같은 프로젝트 구조를 가정하겠습니다.



```Plaintext
MyProject/              <-- (여기가 루트: BASE_DIR)
│
├── main.py             <-- (현재 실행 중인 코드 파일)
├── .env                <-- (1. 루트에 있는 파일)
│
├── config/             <-- (폴더)
│   └── settings.yaml   <-- (2. 루트 > 폴더 > 파일)
│
└── models/             <-- (폴더)
    └── v1/             <-- (하위 폴더)
        └── model.bin   <-- (3. 루트 > 폴더 > 폴더 > 파일)
```

---

### 💻 파이썬 코드 예시



```Python
from pathlib import Path

# [Step 0] 기준점 잡기 (가장 중요!)
# __file__: 현재 실행 중인 파일(main.py)의 위치
# .resolve(): 윈도우/맥/리눅스 어디든 절대 경로로 변환
# .parent: 파일이 있는 '폴더' 경로 (즉, MyProject 루트 폴더)
BASE_DIR = Path(__file__).resolve().parent

print(f"프로젝트 루트 경로: {BASE_DIR}")
print("-" * 30)


# [Case 1] 루트에 바로 있는 파일 (.env)
# 설명: 루트 경로 뒤에 바로 파일 이름을 붙입니다.
root_file = BASE_DIR / ".env"

print(f"1. 루트 파일 경로:\n   {root_file}")


# [Case 2] 루트 > 폴더 > 파일 (config/settings.yaml)
# 설명: 슬래시(/) 연산자를 사용해 '폴더명'과 '파일명'을 순서대로 이어 붙입니다.
folder_file = BASE_DIR / "config" / "settings.yaml"

print(f"2. 폴더 내 파일 경로:\n   {folder_file}")


# [Case 3] 루트 > 폴더 > 폴더 > 파일 (models/v1/model.bin)
# 설명: 폴더 깊이가 깊어져도 계속 / 를 사용하여 직관적으로 연결하면 됩니다.
deep_file = BASE_DIR / "models" / "v1" / "model.bin"

print(f"3. 깊은 폴더 내 파일 경로:\n   {deep_file}")


# [Bonus] 실제 파일이 존재하는지 체크하기
if deep_file.exists():
    print("\n[확인] 모델 파일이 실제로 존재합니다!")
else:
    print(f"\n[주의] {deep_file} 위치에 파일이 없습니다.")
```

### 💡 핵심 포인트

1. **`BASE_DIR` (기준점):**
    
    - `Path(__file__).resolve().parent`는 일종의 공식입니다. "나(코드) 지금 어디 있지?"를 자동으로 계산해서 기준점을 잡아줍니다.
        
2. **`/` 연산자:**
    
    - `pathlib`의 가장 큰 장점입니다. 문자열 더하기(`+`) 대신 나눗셈 기호(`/`)를 쓰면, 운영체제(윈도우 `\`, 맥 `/`)에 맞춰 알아서 경로를 만들어줍니다.
        

이 구조를 사용하면 프로젝트 폴더를 통째로 다른 컴퓨터로 옮겨도 **코드를 단 한 줄도 수정할 필요가 없습니다.**

네, 앞서 설명해 드린 **`pathlib`** 방식과 비교하실 수 있도록, **1. 고전적인 방식 (`os.path`)**과 **2. 환경변수 방식 (`python-dotenv`)**도 똑같은 시나리오로 정리해 드리겠습니다.

# #경로/ospath
### 1. `os.path` 방식 (전통적인 방식)

파이썬 3.4 이전이나 레거시 코드에서 가장 많이 보이는 방식입니다. 문자열을 합치는(`join`) 방식이라 코드가 조금 더 길어집니다.



```Python
import os

# 이렇게만 쓰면 현재 파일과 같은 위치(동일 경로)에 있는 `datasets` 폴더를 의미
DATASETS_DIR = os.path.join(os.path.dirname(__file__), "datasets")

# [Step 0] 기준점 잡기
# __file__: 현재 파일, abspath: 절대 경로 변환, dirname: 폴더 경로 추출
BASE_DIR = os.path.dirname(os.path.abspath(__file__))

print(f"프로젝트 루트 경로: {BASE_DIR}")
print("-" * 30)


# [Case 1] 루트에 바로 있는 파일 (.env)
# 설명: os.path.join 함수 안에 기준 경로와 파일명을 쉼표로 나열합니다.
root_file = os.path.join(BASE_DIR, ".env")

print(f"1. 루트 파일 경로:\n   {root_file}")


# [Case 2] 루트 > 폴더 > 파일 (config/settings.yaml)
# 설명: 폴더명과 파일명을 순서대로 쉼표(,)로 구분해 넣어주면 운영체제에 맞게 합쳐줍니다.
folder_file = os.path.join(BASE_DIR, "config", "settings.yaml")

print(f"2. 폴더 내 파일 경로:\n   {folder_file}")


# [Case 3] 루트 > 폴더 > 폴더 > 파일 (models/v1/model.bin)
# 설명: 깊이가 깊어지면 인자를 계속 추가하면 됩니다.
deep_file = os.path.join(BASE_DIR, "models", "v1", "model.bin")

print(f"3. 깊은 폴더 내 파일 경로:\n   {deep_file}")
```

# #경로/dotenv
### 2. `python-dotenv` 방식 (보안 및 설정 관리)

경로 자체를 코드에 적지 않고, 외부 파일(`.env`)에 적어둔 뒤 불러오는 방식입니다. 협업 시 각자 폴더 구조가 다를 때 유용합니다.

**준비물: `.env` 파일 (프로젝트 루트에 생성)**



```Properties
# .env 파일 내용
CONFIG_FILE_NAME="settings.yaml"
MODEL_DIR_NAME="models/v1"
DEEP_FILE_NAME="model.bin"
```

**파이썬 코드 (`main.py`)**



```Python
import os
from dotenv import load_dotenv

# [Step 0] .env 파일 로드 및 기준점 잡기
load_dotenv() # .env 파일의 내용을 환경변수로 불러옴
BASE_DIR = os.path.dirname(os.path.abspath(__file__))


# [Case 1] 루트에 바로 있는 파일 (.env 파일 자체)
# 설명: 보통 .env 파일 위치는 고정이므로 직접 지정하거나 라이브러리가 자동 탐색합니다.
root_file = os.path.join(BASE_DIR, ".env")

print(f"1. 루트 파일 경로:\n   {root_file}")


# [Case 2] 루트 > 폴더 > 파일 (config/settings.yaml)
# 설명: 파일명("settings.yaml")을 환경변수에서 가져와서 합칩니다.
config_name = os.getenv("CONFIG_FILE_NAME") # .env에서 값 가져오기
folder_file = os.path.join(BASE_DIR, "config", config_name)

print(f"2. 폴더 내 파일 경로 (설정값 이용):\n   {folder_file}")


# [Case 3] 루트 > 폴더 > 폴더 > 파일 (models/v1/model.bin)
# 설명: 경로의 일부나 전체를 환경변수에서 가져와 조립합니다.
model_dir = os.getenv("MODEL_DIR_NAME") # "models/v1"
model_name = os.getenv("DEEP_FILE_NAME") # "model.bin"

# BASE_DIR + models/v1 + model.bin
deep_file = os.path.join(BASE_DIR, model_dir, model_name)

print(f"3. 깊은 폴더 내 파일 경로 (설정값 이용):\n   {deep_file}")
```

### 💡 3가지 방식 한눈에 비교

|**특징**|**Pathlib (추천)**|**os.path (구식)**|**Dotenv (설정)**|
|---|---|---|---|
|**코드 스타일**|`BASE_DIR / "folder" / "file"`|`join(BASE_DIR, "folder", "file")`|`join(BASE_DIR, os.getenv("FILE"))`|
|**가독성**|매우 좋음 (직관적)|보통 (괄호가 많음)|낮음 (파일을 왔다 갔다 해야 함)|
|**목적**|**현대적인 파일 경로 조작**|구버전 호환성 유지|**비밀번호/경로 등 설정 분리**|

**결론적으로:**

코드를 짜실 때는 **`pathlib`**을 기본으로 사용하시되, 보안이 필요한 API 키나 변경이 잦은 모델 경로 등은 **`pathlib` + `.env`**를 조합해서 사용하는 것이 "Best Practice(모범 사례)"입니다.

# .parent #경로/parent
네, **`.parent`를 여러 번 사용하는 방법(상위 폴더 이동)**과 **Jupyter Notebook 환경**에서의 경로 설정법은 실무에서 정말 자주 마주치는 상황입니다.

각각 명확한 예시와 함께 정리해 드리겠습니다.

---

### 1. `.parent` 연쇄 사용 (깊은 폴더에서 탈출하기)

폴더가 아주 깊숙이 있을 때, 프로젝트의 최상위 폴더(Root)로 올라가기 위해 `.parent`를 여러 번 연결해서 사용합니다.

**📂 가정하는 폴더 구조**

Plaintext

```
MyProject/                  <-- (최상위 목표: ROOT)
│
├── data/
│   └── text.txt            <-- (가져오려는 파일)
│
└── src/
    └── utils/
        └── file_loader.py  <-- (현재 코드 위치: 깊음)
```

**💻 파이썬 코드 (`file_loader.py`)**

Python

```
from pathlib import Path

# [Step 1] 현재 파일의 위치 구하기
# 결과: .../MyProject/src/utils/file_loader.py
current_file = Path(__file__).resolve()

# [Step 2] .parent를 연쇄적으로 사용하여 위로 올라가기
# .parent (1번): .../MyProject/src/utils  (현재 파일의 폴더)
# .parent (2번): .../MyProject/src        (한 단계 위)
# .parent (3번): .../MyProject            (두 단계 위 -> 프로젝트 루트!)
project_root = current_file.parent.parent.parent

print(f"프로젝트 루트: {project_root}")

# [Step 3] 루트에서 다시 아래로 내려가서 파일 찾기
target_file = project_root / "data" / "text.txt"

print(f"타겟 파일 경로: {target_file}")
```

> **Tip:** `.parent`의 개수는 **"내가 탈출해야 하는 폴더 깊이 + 1(파일 자체)"**라고 생각하면 쉽습니다.

---

### 2. Jupyter Notebook (`.ipynb`) 환경일 때

Jupyter Notebook에서는 **`__file__` 변수가 존재하지 않습니다.** (이걸 쓰면 `NameError`가 발생합니다).

대신 **`Path.cwd()`** (Current Working Directory)를 사용해야 합니다.
==노트북 파일이 있는 폴더가 현재 위치가 됩니다.==

질문하신 내용은 **"출발점이 '파일(File)'이냐 '폴더(Folder)'냐의 차이"** 때문에 발생합니다.

해당 코드는 **"소스 파일은 `src` 폴더에, 노트북은 `notebooks` 폴더에 있다"**는 일반적인 프로젝트 구조를 가정하고 작성된 것입니다. 그 차이를 그림으로 명확히 보여드릴게요.

---

### 1. 가정하고 있는 폴더 구조

Plaintext

```
Project/                    <-- (우리가 가고 싶은 목적지: ROOT)
│
├── notebooks/              <-- (노트북 폴더)
│   └── analysis.ipynb      <-- (현재 실행 중인 주피터 노트북)
│
└── src/                    <-- (소스코드 폴더)
    └── main.py             <-- (현재 실행 중인 파이썬 파일)
```

이 구조에서 `Project/` 폴더(루트)로 가기 위해 필요한 단계를 비교해 보겠습니다.

### 2. 왜 차이가 날까? (핵심 비교)

파이썬 파일(.py)은 **"나 자신(파일)"**에서 출발하고, 주피터 노트북(.ipynb)은 **"내가 있는 방(폴더)"**에서 출발한다고 생각하시면 됩니다.

|**구분**|**파이썬 스크립트 (.py)**|**주피터 노트북 (.ipynb)**|
|---|---|---|
|**명령어**|`Path(__file__)`|`Path.cwd()`|
|**출발점**|`.../src/main.py` (**파일**)|`.../notebooks` (**폴더**)|
|**1번 parent**|`.../src` (파일 껍질 벗김)|`.../Project` (바로 상위 폴더)|
|**2번 parent**|`.../Project` (상위 폴더)|(필요 없음)|
|**결론**|**부모를 2번 호출해야 함**|**부모를 1번만 호출하면 됨**|

---

### 3. 단계별 상세 이동 경로

#### A. 파이썬 파일 (`src/main.py`)의 경우

파일 이름까지 포함된 경로에서 시작하기 때문에, **파일명 떼기** 작업이 한 번 더 필요합니다.

1. `Path(__file__)`: `.../Project/src/main.py` (출발)
    
2. `.parent` (1번째): `.../Project/src` (**파일명이 떨어져 나감**)
    
3. `.parent` (2번째): `.../Project` (**상위 폴더로 이동** -> 도착!)
    

#### B. 주피터 노트북 (`notebooks/analysis.ipynb`)의 경우

주피터의 `cwd()`(Current Working Directory)는 현재 작업 중인 **폴더 경로**만 줍니다. 파일명은 포함되지 않습니다.

1. `Path.cwd()`: `.../Project/notebooks` (출발, **이미 폴더임**)
    
2. `.parent` (1번째): `.../Project` (**상위 폴더로 이동** -> 도착!)

### 🚀 요약

- **`.py` 파일:** "파일명" -> "폴더" -> "상위 폴더" (**2단계**)
    
- **`.ipynb` 노트북:** "폴더" -> "상위 폴더" (**1단계**)
    

만약 프로젝트 구조가 달라서 파일 위치가 바뀐다면 `.parent`의 횟수도 그에 맞춰 조절해주시면 됩니다!

**📂 가정하는 상황**

Plaintext

```
MyProject/
├── notebooks/
│   └── analysis.ipynb      <-- (현재 실행 중인 노트북)
└── data/
    └── dataset.csv         <-- (가져오려는 데이터)
```

**💻 Jupyter Notebook 코드 셀**

Python

```
from pathlib import Path

# [중요] 노트북에서는 __file__ 대신 cwd()를 씁니다.
# 보통 노트북 파일이 있는 폴더가 현재 위치가 됩니다.
# 결과: .../MyProject/notebooks
current_dir = Path.cwd()

print(f"현재 노트북 위치: {current_dir}")

# [Step 1] 상위 폴더(MyProject)로 이동
# notebooks 폴더에서 나가야 하므로 .parent를 한 번 씁니다.
project_root = current_dir.parent

print(f"프로젝트 루트: {project_root}")

# [Step 2] 데이터 파일 경로 설정
data_path = project_root / "data" / "dataset.csv"

# 확인
import pandas as pd
# df = pd.read_csv(data_path) 
print(f"데이터 경로: {data_path}")
```

### 🚀 [꿀팁] 스크립트(.py)와 노트북(.ipynb) 모두 작동하는 코드

개발을 하다 보면 코드를 노트북에서 실험하다가 `.py` 파일로 옮길 때가 많습니다. 이때마다 코드를 고치기 귀찮으시다면, 아래의 **"만능 코드"**를 사용하세요.

Python

```
from pathlib import Path
import sys

# 1. 현재 실행 환경이 노트북인지 스크립트인지 판별하여 루트 찾기
try:
    # .py 파일로 실행될 때
    PROJECT_ROOT = Path(__file__).resolve().parent.parent # 폴더 구조에 맞춰 .parent 개수 조절
except NameError:
    # Jupyter Notebook에서 실행될 때 (__file__ 없음)
    PROJECT_ROOT = Path.cwd().parent # 폴더 구조에 맞춰 .parent 개수 조절

# 2. 이제 PROJECT_ROOT를 기준으로 경로를 잡으면 어디서든 동작합니다.
data_dir = PROJECT_ROOT / "data"
model_dir = PROJECT_ROOT / "models"

print(f"설정된 루트 경로: {PROJECT_ROOT}")
```

이 방식을 사용하면 코드를 복사해서 어디로 옮기든 경로 에러 걱정이 사라집니다.
