## DB기초지식

RDB(Relational Database)는 데이터를 행(Row)과 열(Column)로 구성된 2차원 형태의 테이블에 저장하고, 각 테이블 간의 논리적인 관계를 수학적 집합론에 기반하여 정의하고 관리하는 시스템입니다.
### RDB의 존재 이유

데이터의 중복 저장을 원천적으로 차단하고, 데이터의 무결성(정확성과 일관성)을 엄격하게 보장하기 위해 존재합니다. 데이터를 여러 테이블로 나누어 저장한 뒤 필요할 때마다 논리적으로 연결(Join)하여 조회하므로, 정보의 갱신이나 삭제가 발생했을 때 데이터의 불일치가 생기는 것을 방지

## SQLite (초경량 파일형 데이터베이스)

우리가 흔히 아는 크고 무거운 서버형 데이터베이스(MySQL, Oracle 등)와 달리, **파일 하나로 동작하는 초소형 데이터베이스**입니다.  
스마트폰 앱이나 웹 브라우저 내부, 소규모 데스크탑 프로그램(예: Cursor, Claude Code 로컬 도구)에서 데이터를 저장할 때 가장 많이 쓰입니다.

- **AI/시맨틱 검색과의 관계:** 원래는 텍스트만 저장했지만, 최근 `sqlite-vec` 같은 확장 기능을 설치하면 AI가 문장을 변환한 숫자 데이터(벡터, Vector)를 저장하고 유사도를 검색할 수 있게 되었습니다.
    
- **비용 (완전 무료):** 완벽한 **무료(퍼블릭 도메인)**입니다. 내 컴퓨터나 서버에 파일 하나만 생성하면 되므로 구독료나 사용료가 전혀 발생하지 않습니다.
## Qdrant (전문 AI 벡터 데이터베이스)

오직 **"AI 시맨틱 검색(벡터 검색)"을 위해 특화되어 만들어진 최신 데이터베이스**입니다.[](https://qdrant.tech/)​  
수백만, 수천만 개의 문서나 코드 라인을 순식간에 읽고 "이 질문과 의미가 가장 비슷한 코드"를 찾아내는 데(RAG 기술) 최적화되어 있습니다. 속도가 매우 빠르고 대규모 처리에 강합니다.

- **AI/시맨틱 검색과의 관계:** Claude Code나 Cursor 같은 AI 에이전트에 회사 전체의 방대한 코드베이스나 수만 장의 문서를 학습시키고 검색하게 만들 때 메인 엔진으로 쓰입니다.
- **비용 (오픈소스 무료 + 클라우드 유료):**
    
    - **자체 호스팅 (무료):** Qdrant는 오픈소스이므로, 내 컴퓨터나 개인 서버(AWS, 회사 서버 등)에 직접 설치해서 쓰면 **평생 무료**입니다. (서버 구동용 전기세/호스팅 비만 듭니다).[](https://www.buildmvpfast.com/tools/api-pricing-estimator/qdrant)​
        
    - **클라우드 Free 티어 (무료):** Qdrant Cloud에 가입하면 **1GB 용량의 클러스터를 평생 무료**로 제공합니다. (코드베이스가 수십만 줄 이하인 개인/소규모 프로젝트는 이 무료 티어로 충분합니다 ).
        
    - **클라우드 유료 플랜:** 서버 관리를 맡기고 대규모 데이터를 쓸 때 사용하며, 시간당 약 $0.01부터 시작해 사용한 만큼(서버 자원, 용량) 비용을 냅니다.

## 1. Qdrant: "검색 품질과 하이브리드(BM25+Dense)가 최우선일 때"

Qdrant는 오직 벡터 검색과 AI 애플리케이션을 위해 깎아 만든 **전문 벡터 DB**입니다.​

- **장점:**
    
    - **완벽한 하이브리드 검색 지원:** 예전에 Supabase에서 `pg_search` 패키지가 안 돼서 고생하셨던 기억이 있으실 겁니다. Qdrant는 **내부적으로 Sparse Vector(BM25 역할)와 Dense Vector를 동시에 완벽하게 지원**하며, 자체적인 점수 병합(Score fusion)까지 기본 제공합니다. 추가 Python 랭킹 로직 없이 DB 단에서 빠르고 정확하게 끝납니다.[](https://agentset.ai/vector-databases/compare/lancedb-vs-qdrant)​
        
    - **메타데이터 필터링 속도:** 페이로드(Payload) 기반 필터링이 강력해서, 특정 사용자나 폴더 내의 코드만 검색할 때 속도 저하가 없습니다.[](https://slashdot.org/software/comparison/LanceDB-vs-Qdrant/)​​
        
- **단점:**
    
    - 데이터를 모두 RAM에 올리는 구조라 인프라 비용(메모리)이 꽤 듭니다 (단, 1GB 무료 클라우드가 있어 소규모는 무방).
        
- **추천 상황:** Claude Code에 최고 품질의 의미/키워드 동시 검색(MCP)을 붙이거나, 실무 프로덕션 RAG를 구축할 때 가장 좋습니다.​
    

## 2. LanceDB: "로컬 에이전트 / 서버리스 비용 절감이 최우선일 때"

LanceDB는 별도의 서버를 띄울 필요 없이 파일 형태로 동작하는 **임베디드 벡터 DB (벡터계의 SQLite)** 입니다. 최근 AI 엔지니어들 사이에서 극찬을 받고 있습니다.

- **장점:**
    
    - **압도적인 가벼움과 비용:** RAM을 상시 점유하는 Qdrant와 달리, 디스크(S3 등 객체 스토리지)에 두고 필요할 때만 연산합니다. 아이들(Idle) 상태일 때 메모리를 고작 4MB만 차지합니다.
        
    - **Python/로컬 AI 생태계 찰떡궁합:** pandas 데이터프레임이나 Arrow 포맷과 바로 호환되며, 로컬에서 돌아가는 Claude Code 커스텀 도구나 로컬 에이전트를 만들 때 셋업이 0초 걸립니다. 내장 Full-text search(FTS)도 지원합니다.
        
- **단점:** 기존 RDB의 트랜잭션 관리나 복잡한 관계형 쿼리는 불가능합니다.
    
- **추천 상황:** 내 PC에서 가볍게 돌아가는 로컬 AI 도구를 만들거나, 수백만 건의 데이터를 비용 없이 S3에 올려두고 검색하고 싶을 때 최고입니다.
    

## 3. Supabase (pgvector): "기존 RDB와 통합 관리가 최우선일 때"

사용자님이 잘 아시는 대로, PostgreSQL 기반의 RDB에 벡터 기능을 얹은 형태입니다.​

- **장점:** 백오피스 데이터(유저 정보, 결제 내역 등)와 벡터 데이터를 SQL 조인(JOIN) 한 방에 처리할 수 있습니다. 아키텍처가 단순해집니다.​
    
- **단점:** 전문 검색 엔진이 아니다 보니, 규모가 커지거나 정교한 하이브리드 검색(BM25 결합 등)을 하려면 확장이 막혀있거나 직접 파이썬으로 우회해서 개발해야 하는 병목이 생깁니다.
    
- **추천 상황:** 굳이 DB를 하나 더 늘리기 싫고, 이미 Supabase에 유저 데이터가 다 모여있는 풀스택 앱을 개발할 때 좋습니다.
