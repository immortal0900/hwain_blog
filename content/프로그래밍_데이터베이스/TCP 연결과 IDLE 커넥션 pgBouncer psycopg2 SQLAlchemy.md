## TCP 연결 (TCP Connection)

두 컴퓨터가 데이터를 주고받기 위해 만드는 **통신 회선**입니다.

```
[Railway 서버]  ←――― TCP 연결 ―――→  [Supabase DB]
   IP: 1.2.3.4                        IP: 5.6.7.8
   Port: 54321                         Port: 5432
```

TCP 연결이 성립되면 양쪽이 서로의 IP와 포트를 기억하고, 이 회선을 통해 SQL 쿼리를 보내고 결과를 받습니다. 웹 브라우저가 서버에 접속할 때도, 앱이 DB에 접속할 때도 전부 TCP 연결이 기반입니다.

**만드는 데 비용이 듭니다** — 3-way handshake(SYN → SYN-ACK → ACK)라는 3단계 확인 절차를 거쳐야 하고, DB의 경우 인증까지 포함하면 수십~수백 ms가 걸립니다. 그래서 SQLAlchemy는 한 번 만든 TCP 연결을 **풀(Pool)에 보관해두고 재사용**합니다.

## idle 커넥션 (유휴 커넥션)

**TCP 연결이 살아있지만, 아무 데이터도 오가지 않는 상태**입니다.

```
시간   상태              TCP 연결   SQL 쿼리

00:00  검색 실행          살아있음    SELECT ... → 결과 반환
00:01  결과 받음          살아있음    (없음) ← idle 시작
00:02  (다른 에이전트 작업 중) 살아있음    (없음)
  :
13:00  13분째 쿼리 없음    살아있음    (없음) ← 13분간 idle
       pgBouncer: "이 커넥션 끊겠다"
```

TCP 연결 자체는 유지되어 있지만, **SQL 쿼리가 오가지 않는 상태**가 idle입니다.

pgBouncer가 idle 커넥션을 끊는 이유는 단순합니다 — **DB 서버의 커넥션 수에는 한계가 있기 때문입니다.** 아무도 안 쓰는 커넥션이 자리를 차지하고 있으면 다른 클라이언트가 접속하지 못합니다. 그래서 일정 시간(~13분) 동안 쿼리가 없으면 "이 클라이언트는 더 이상 안 쓰나보다"라고 판단하고 회수합니다

## 각각의 역할 — 한 줄 정의

| 이름             | 한 줄 정의                                                 | 비교                           |
| -------------- | ------------------------------------------------------ | ---------------------------- |
| **PostgreSQL** | 데이터를 실제로 저장하는 **데이터베이스**                               | 은행 금고                        |
| **PGVector**   | PostgreSQL에 "벡터 유사도 검색" 기능을 추가하는 **확장 기능**             | 금고에 설치한 특수 검색 장치             |
| **pgBouncer**  | DB 앞에서 커넥션을 관리하는 **중개자(Pooler)**                       | 금고실 앞 접수 창구                  |
| **SQLAlchemy** | Python 코드에서 DB에 SQL을 보내는 **ORM/엔진**                    | "SELECT ..." 같은 요청서를 작성하는 도구 |
| **psycopg2**   | SQLAlchemy가 PostgreSQL과 **실제 TCP 통신**할 때 사용하는 **드라이버** | 요청서를 창구까지 배달하는 배달원           |

## 데이터가 흐르는 순서

```
Python 코드
  "대치동 관련 정책 문서 검색해줘"
    │
    ▼
SQLAlchemy (ORM/엔진)
  → Python 코드를 SQL로 변환
  → "SELECT * FROM vectors WHERE similarity(...) > 0.8"
    │
    ▼
psycopg2 (드라이버)
  → 이 SQL을 TCP 패킷으로 만들어서 네트워크로 전송
    │
    ▼  (TCP 연결)
    │
pgBouncer (커넥션 중개자)
  → "이 클라이언트의 세션이 유효한가?" 확인
  → 유효하면 뒤쪽 PostgreSQL로 전달
    │
    ▼
PostgreSQL + PGVector (DB + 벡터 검색)
  → SQL 실행 → 유사도 높은 문서 반환
```

## 이번 에러에서 각각의 역할

| 이름             | 이번 에러에서 한 일                                                          |
| -------------- | -------------------------------------------------------------------- |
| **SQLAlchemy** | 풀에 커넥션이 있으니 "유효하다"고 판단 → 죽은 커넥션을 꺼냄 (**원인 제공**)                      |
| **psycopg2**   | TCP keepalive 패킷을 30초마다 보냄 → 하지만 pgBouncer에게 의미 없었음 (**방어 실패**)      |
| **pgBouncer**  | 13분간 SQL 쿼리 없음 → 세션 종료 (**직접 원인**)                                   |
| **PGVector**   | `engine_args` 없이 생성됨 → SQLAlchemy 기본값(pre_ping=False) 적용 (**설정 누락**) |
