파인튜닝 기술의 근간인 **LoRA**와 그 진화형인 **DoRA**에 대해 핵심 위주로 정리해 드릴게요.

---

## 1. LoRA (Low-Rank Adaptation): "옆길 만들기"

### 사용 의도 및 근거

거대 모델(LLM)의 수십억 개 파라미터를 다 수정하는 것은 시간과 비용 면에서 불가능에 가깝습니다. LoRA는 **"핵심 지능(Pre-trained Weights)은 그대로 두고, 특정 작업에 필요한 작은 근육(Adapter)만 키우자"**는 의도로 탄생했습니다.

### 원리

모델의 큰 행렬($W$) 옆에 아주 작은 두 개의 행렬($A, B$)을 덧붙입니다.

- **$W$ (Frozen):** 원래 모델의 지식. 학습하지 않고 고정합니다.
    
- **$A, B$ (Trainable):** 학습 가능한 작은 행렬. 입력 데이터를 낮은 차원으로 줄였다가($A$) 다시 원래 차원으로 늘리며($B$) 변화량만 학습합니다.
    
- **최종 계산:** $W + (A \times B)$. 즉, 원래 지식에 학습된 변화량을 더해 결과를 냅니다.
    

---

## 2. DoRA (Weight-Decomposed Low-Rank Adaptation): "크기와 방향의 분리"

### 사용 의도 및 근거

LoRA는 학습 효율은 좋지만, 가중치의 **'크기(Magnitude)'**와 **'방향(Direction)'**을 한꺼번에 업데이트하기 때문에 정교함이 떨어질 때가 있습니다. DoRA는 이 두 요소를 분리하여 **전체 파인튜닝(Full Fine-Tuning)과 거의 유사한 성능**을 내기 위해 만들어졌습니다.

### 원리

가중치를 두 성분으로 수학적으로 분해(Decomposition)합니다.

1. **Magnitude ($m$):** 가중치의 세기(크기).
    
2. **Direction ($V$):** 가중치가 향하는 방향.

- **DoRA의 핵심:** 방향($V$) 부분에만 LoRA를 적용하고, 크기($m$)는 별도로 세밀하게 조정합니다.
    

---

## 3. LoRA vs DoRA 차이점

|**구분**|**LoRA**|**DoRA**|
|---|---|---|
|**핵심 개념**|낮은 차원의 행렬을 추가하여 학습|가중치를 크기와 방향으로 분해 후 학습|
|**성능**|훌륭하지만 전체 튜닝보다는 약간 낮음|**전체 파인튜닝에 근접하는 최고 수준**|
|**학습 속도**|매우 빠름|LoRA보다 약간 느림 (분해 연산 추가)|
|**메모리 사용**|매우 적음|LoRA와 비슷하거나 아주 약간 더 사용|
|**안정성**|가끔 학습이 불안정할 수 있음|방향과 크기를 따로 잡아주어 **더 안정적임**|

## 4. 쓰는 방법 (PEFT 라이브러리 기준)

질문자님이 사용하시는 `peft` 라이브러리에서 설정값 하나만 바꾸면 바로 적용할 수 있습니다.

### LoRA 설정

```Python
from peft import LoraConfig, get_peft_model

config = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules=["q_proj", "v_proj"],
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM"
)
model = get_peft_model(base_model, config)
```

### DoRA 설정 (LoRA 설정에서 하나만 추가)

```Python
config = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules=["q_proj", "v_proj"],
    use_dora=True,  # <--- 이 옵션만 True로 바꾸면 DoRA가 됩니다!
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM"
)
model = get_peft_model(base_model, config)
```

## 5. 요약: 언제 무엇을 써야 할까?

- **LoRA를 쓰는 경우:** 가장 빠르게, 가장 적은 자원으로 적당히 똑똑한 모델을 만들고 싶을 때 (표준적인 선택).
    
- **DoRA를 쓰는 경우:** 자원은 LoRA만큼만 쓰면서, 성능은 전체 파인튜닝 급으로 끌어올리고 싶을 때 (성능 중심의 선택).
    

최근 2026년 기준으로는 **DoRA**가 성능 면에서 확실한 우위를 점하고 있어, 약간의 연산 오버헤드를 감수하더라도 DoRA를 사용하는 추세입니다.

**질문자님의 보이스피싱 탐지 프로젝트에서 정확도가 조금 아쉽다면, 옵션에서 `use_dora=True`를 켜고 다시 학습해 보시는 건 어떨까요?**


# 파라미터 쓰임에 대하여
```python
from peft import LoraConfig, get_peft_model

config = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules=["q_proj", "v_proj"],
    use_dora=True,  # <--- 이 옵션만 True로 바꾸면 DoRA가 됩니다!
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM"
)
model = get_peft_model(base_model, config)
```
작성해주신 `LoraConfig`의 파라미터들은 모델을 **'얼마나, 어디를, 어떤 방식으로'** 학습시킬지 결정하는 핵심 조절 나사들입니다. 각 파라미터의 존재 이유와 의미를 정리해 드릴게요.

---

## 1. `r=16` (Rank)

- **의미:** LoRA 행렬의 **'두께(차원)'**입니다.
    
- **존재 이유:** 원래 모델의 가중치는 거대한 행렬($d \times d$)입니다. 이걸 그대로 학습하기 힘드니 아주 얇은 두 개의 행렬($d \times r$ 과 $r \times d$)로 쪼개는데, 이때의 중간 통로 크기가 `r`입니다.
    
- **영향:** `r`이 커질수록 모델이 더 복잡한 정보를 배울 수 있지만, 메모리 사용량이 늘어나고 학습 속도가 느려집니다. 보통 8, 16, 32 정도로 설정합니다.
    

## 2. `lora_alpha=32` (Scaling Factor)

- **의미:** 학습된 변화량을 **'얼마나 강하게 반영할지'** 결정하는 배율입니다.
    
- **존재 이유:** 실제 계산 시 `학습된 값 * (lora_alpha / r)` 공식을 사용합니다.
    
- **영향:** 보통 `r` 값의 2배 정도로 설정하며, 이 값이 클수록 새로 배운 지식(LoRA)이 기존 지식(Base Model)보다 더 큰 목소리를 내게 됩니다. 즉, **학습 강도**를 조절하는 역할을 합니다.
    

## 3. `target_modules=["q_proj", "v_proj"]`

- **의미:** 모델의 수많은 부품 중 **'어느 부위에 포스트잇(LoRA)을 붙일 것인가'**를 지정합니다.
    
- **존재 이유:** 모델 전체를 학습시키는 대신, 문맥 파악에 가장 중요한 Attention 모듈(`q`, `k`, `v`, `o`)이나 지식 저장소인 FFN 모듈(`gate`, `up`, `down`)만 골라서 학습시켜 효율을 높이기 위함입니다.
    
- **영향:** 많이 지정할수록 성능은 좋아지지만 VRAM을 더 많이 소모합니다.
    

## 4. `use_dora=True`

- **의미:** 가중치를 **'크기(Magnitude)'와 '방향(Direction)'**으로 나누어 학습하는 **DoRA** 기법을 쓸지 여부입니다.
    
- **존재 이유:** 단순 LoRA는 크기와 방향을 동시에 바꿔서 가끔 학습이 정교하지 못할 때가 있습니다. DoRA는 이를 분리해서 학습 안정성과 성능을 전체 파인튜닝 수준으로 끌어올립니다.
    
- **영향:** 켜면 성능은 좋아지지만, 학습 속도가 아주 약간 느려질 수 있습니다.
    

## 5. `lora_dropout=0.05`

- **의미:** 학습 중에 무작위로 LoRA 노드의 5%를 **'꺼버리는'** 비율입니다.
    
- **존재 이유:** 모델이 특정 데이터에만 너무 과하게 집착해서 달달 외워버리는 **과적합(Overfitting)** 현상을 방지하기 위함입니다.
    
- **영향:** 모델이 좀 더 유연해지고 처음 보는 데이터(Generalization)에도 대처를 잘하게 됩니다.
    

## 6. `bias="none"`

- **의미:** 모델의 편향(bias) 파라미터를 학습할지 결정합니다.
    
- **존재 이유:** 파라미터를 최소한으로 유지하기 위해 보통 `none`으로 둡니다.
    
- **영향:** `all`이나 `lora_only`로 설정할 수 있지만, 특수한 경우가 아니면 건드리지 않는 것이 일반적입니다.
    

## 7. `task_type="CAUSAL_LM"`

- **의미:** 어떤 종류의 모델 작업을 수행하는지 알려줍니다.
    
- **존재 이유:** Gemma 같은 언어 모델(다음 단어 예측)은 `CAUSAL_LM`입니다. 이 설정에 따라 내부적으로 손실 함수(Loss) 계산 방식이 최적화됩니다.

### 한눈에 요약 (비유)

|**파라미터**|**비유**|**핵심 역할**|
|---|---|---|
|**`r`**|연습장의 크기|학습 가능한 용량 결정|
|**`alpha`**|목소리 크기|새로 배운 지식의 반영 강도|
|**`target_modules`**|공부할 과목|학습할 특정 부위 지정|
|**`use_dora`**|공부 방법론|학습 정밀도 향상|
|**`dropout`**|가끔 한눈팔기|암기 방지 (응용력 향상)|

이 파라미터들 중 **`r`과 `target_modules`**가 VRAM 사용량에 가장 직접적인 영향을 줍니다. 현재 그래픽 카드 메모리가 꽉 차서 에러가 난다면 `r`을 낮추거나 `target_modules`의 개수를 줄여보시면 됩니다.
