# 파인튜닝 종합 정리 (기초 → SOTA)

기초 사전지식부터 최신 SOTA(State-Of-The-Art, 현시점 최고 성능 기법)까지 한 흐름으로 통합한 마스터 노트. 중복 제거 후 분류 재구성함.

관련 노트: [[LoRA vs DoRA]], [[GGUF란_가중치,토크나이저, 모델구조를 파일 하나로]]

**전체 포함 관계**:
```
파인튜닝 (Fine-tuning)
├─ Full Fine-tuning (전체 파라미터 업데이트)
└─ PEFT (Parameter-Efficient Fine-Tuning)
    ├─ LoRA 계열
    │   ├─ LoRA
    │   ├─ QLoRA (양자화 + LoRA)
    │   └─ DoRA (크기/방향 분해 + LoRA)
    ├─ Adapter Tuning
    ├─ Prefix/Prompt Tuning
    └─ IA³
```

## 1. 숫자 표현 형식 (Precision)

**핵심**: 컴퓨터는 모든 수를 비트(bit, 0/1 단위)로 저장함. `32`, `16`, `4`는 **숫자 하나를 몇 비트로 표현할지** 정한 약속임. AI 가중치는 `0.00231` 같은 소수값이 대부분이라 float(Floating Point, 부동소수점)을 씀.

### 부동소수점 내부 구조
16비트 float는 두 파트로 나뉨.
- **부호부(sign)**: 1비트, 양수/음수
- **지수부(exponent)**: 숫자의 **범위(range)** 담당
- **가수부(mantissa)**: 숫자의 **정밀도(precision)** 담당

| 형식 | 전체 비트 | 지수부 | 가수부 | 표현 범위 | 소수점 정밀도 |
|---|---|---|---|---|---|
| **float32** | 32 | 8 | 23 | 약 3.4×10³⁸ | 약 7자리 |
| **float16** | 16 | 5 | 10 | 약 65,504 (좁음) | 약 3자리 |
| **bfloat16** | 16 | 8 | 7 | float32와 동일 | 약 2자리 |

### float16의 약점: Overflow와 NaN

학습 중 행렬곱/덧셈이 수천억 번 반복되면 값이 float16 한계(±65,504)를 초과하며 `inf`(무한대)가 됨. `inf + x` = `NaN`(Not a Number, 미정의 값) → 손실(loss)이 NaN 되면 학습 붕괴.

**bfloat16의 해법**: 지수부를 float32와 같은 8비트로 유지해 **범위는 동일**, 대신 가수부를 줄여 정밀도만 약간 포기. LLM 학습에선 범위가 훨씬 중요하기에 bfloat16이 표준이 됨.

### 직접 확인
```python
import torch
x = torch.tensor(70000.0, dtype=torch.float16)
print(x)  # tensor(inf, dtype=torch.float16) - 범위 초과

y = torch.tensor(70000.0, dtype=torch.bfloat16)
print(y)  # tensor(69632., dtype=torch.bfloat16) - 정상 표현
```

## 2. 양자화 (Quantization)

**정의**: 양자화(Quantization, 연속적인 고정밀 값을 제한된 개수의 이산적 값으로 매핑하는 압축 기법)는 고정밀 float를 적은 비트의 정수 또는 특수 float으로 변환해 메모리/연산 절감.

### 양자화 오차: "눈금 맞춤"의 불가역성
- 원본(float32): `5.1234567` (약 7자리 정밀도)
- 4비트 세계: 표현 가능한 눈금은 $2^4 = 16$개
  - 예: `0, 0.6, 1.2, ..., 5.1, 5.7, ..., 10`
- 저장 시 가장 가까운 눈금 `5.1`로 스냅됨 → `0.0234567`은 영원히 복원 불가

**한마디**: 압축 해제해도 정보가 되살아나지 않음. 양자화는 "복사"가 아니라 "요약"임.

### 일반 4비트 vs NF4 비교

| 구분 | INT4 / RTN (일반 4비트) | **NF4** (Normal Float 4) |
|---|---|---|
| **눈금 방식** | 일정 간격 (선형) | **정규분포에 맞춘 불균등 간격** |
| **설계 근거** | 없음 | AI 가중치는 대부분 0 근처에 몰려있음 |
| **0 근처 정밀도** | 낮음 | **매우 높음** (눈금 촘촘) |
| **양 극단 정밀도** | 낮음 | 낮음 (눈금 듬성) |
| **결과** | 중요한 미세값 뭉개짐 | **핵심 정보 보존** |
| **주 용도** | 추론 전용 | **학습 가능** (QLoRA와 결합) |

**NF4의 트릭**: 가우시안 분포의 분위수(quantile)를 눈금으로 삼음. 확률밀도 높은 0 근처에 눈금을 몰아줌.

### 왜 연산 시 bfloat16으로 복원하나 (float32 아님)

"그릇이 크면 좋지 않나?"라는 오해 해소.

1. **속도**: A100/H100의 Tensor Core(행렬연산 전용 하드웨어)는 bfloat16이 float32보다 2~8배 빠름
2. **대역폭(Bandwidth, 단위시간당 데이터 전송량)**: GPU 내부 버스 용량 한정. 4비트 정보를 32비트로 실어나르면 채널 낭비
3. **충분함**: 이미 4비트 수준 정보라 bfloat16 정밀도(약 2자리)로도 다 담김

**일상 비유**: 편의점 영수증 내용을 A4 용지에 대문짝만하게 프린트할 필요 없음. 메모지 한 장이면 충분.

## 3. PEFT (Parameter-Efficient Fine-Tuning)

**정의**: PEFT(전체 파라미터 중 극소수만 학습해 Full Fine-tuning 성능에 근접하려는 기법군). HuggingFace `peft` 라이브러리가 사실상 표준 구현체.

### LoRA → QLoRA → DoRA 발전 흐름

| 기법 | 핵심 | VRAM (Gemma 9B 기준) |
|---|---|---|
| **Full FT** | 모든 파라미터 업데이트 | 약 360GB (BF16) |
| **LoRA** | 가중치 옆에 얇은 어댑터 추가, 본체 동결 | 약 40GB |
| **QLoRA** | NF4 압축 본체 + LoRA 어댑터 | **약 12GB** (RTX 4090 가능) |
| **DoRA** | 가중치를 크기/방향 분해 후 LoRA 적용 | LoRA와 유사 |

**자세한 비교**: [[LoRA vs DoRA]]

> `load_in_4bit=True` + `bnb_4bit_quant_type="nf4"` = "가장 똑똑한 눈금(NF4)으로 압축해 학습(QLoRA)하겠다"는 선언.

### Unsloth: "엔진 튜닝"

**2026년 개인용 GPU 파인튜닝 사실상 표준 라이브러리.**

- **문제 인식**: 순정 PyTorch/HuggingFace는 범용성 중시라 연산 단계마다 GPU 메모리에 썼다가 다시 읽는 오버헤드 발생
- **해법: 커스텀 커널(Custom Kernel, OpenAI Triton 기반으로 GPU에 직접 보내는 저수준 연산 묶음)**
  - 수십 단계 연산을 하나의 거대 커널로 융합(fusion)해 중간 저장 없이 한 번에 처리
- **효과**:
  - 학습 속도 **2배 이상**
  - VRAM 사용량 **최대 70~80% 감소**
  - 정확도 손실 **0%**
- **역전파 최적화**: 불필요한 중간값(activation)을 저장하지 않고 재계산(gradient checkpointing 고도화)

HuggingFace **TRL**(Transformer Reinforcement Learning, DPO/PPO 등 정렬 학습 표준 라이브러리)와 병행이 현재 표준 스택.

```python
from unsloth import FastLanguageModel

model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="unsloth/gemma-2-9b-bnb-4bit",
    max_seq_length=2048,
    load_in_4bit=True,
    dtype=None,  # 자동 선택 (보통 bfloat16)
)
```

## 4. 학습 효율화 기법

### Packing: "빈 공간 없이 꽉꽉 채우기"

- **일반 방식**: `max_len=512` 설정에서 100단어 문장 투입 시 나머지 412칸을 **0(Padding)**으로 채움 → 0도 연산 대상이라 VRAM과 연산 낭비
- **Packing 방식**: 여러 짧은 대화를 이어 붙여 한 샘플에 몰아넣음
  - 형식 예: `[대화1] <|endoftext|> [대화2] <|endoftext|> [대화3] ...`
- **효과**: 학습 속도 **2~5배** (짧은 대화 데이터셋일수록 극적)

### Flash Attention 2

- **역할**: 긴 문맥(long context, 수천~수만 토큰) 처리 시 어텐션(Attention, 토큰 간 관계 계산) 연산을 물리적으로 가속
- **원리**: GPU SRAM(고속 캐시)과 HBM(고용량 메모리) 간 데이터 이동 최소화
- **현 상태**: 2026년 사실상 필수

### Gradient Checkpointing

- **문제**: 역전파(backpropagation)에 쓸 중간 activation을 다 저장하면 VRAM 폭발
- **해법**: 일부만 저장하고 역전파 시 재계산. VRAM 크게 절감 대신 학습 시간 10~30% 증가
- **권장**: Unsloth는 내부적으로 이미 적용됨

## 5. 정렬(Alignment) / Post-training SOTA

**정의**: 모델을 지시(instruction) 잘 따르고 안전(safety)하게 만드는 단계. RLHF의 복잡성을 벗어나 단순/고효율로 진화 중.

### 흐름: RLHF → DPO → ORPO/SimPO/BPO/GRPO

#### RLHF (Reinforcement Learning from Human Feedback, 사람 피드백 기반 강화학습)
- **구조**: 보상모델(Reward Model) 학습 → PPO(Proximal Policy Optimization, 강화학습 알고리즘)로 정책 학습
- **단점**: 복잡, 불안정, 보상모델 학습 필요
- **대표 사용**: InstructGPT, 초기 ChatGPT

#### DPO (Direct Preference Optimization) - **현재 주류**
- **핵심**: 선호쌍 데이터(Chosen, Rejected)만 주면 모델이 Chosen 쪽 확률을 스스로 높임
- **보상 모델 불필요**: 수학적으로 보상모델을 모델 자체에 흡수
- **장점**: 간단, 안정적, 구현 용이

#### ORPO (Odds Ratio Preference Optimization)
- **기존 2단계**: SFT(Supervised Fine-Tuning, 정답 모방 학습) → DPO(선호 학습)
- **ORPO**: SFT와 선호 학습을 **한 번에** 수행. 정답 형식을 배우면서 "이렇게 답하면 감점" 신호를 동시에 받음
- **효과**: 시간 단축 + 품질 상승

#### BPO (Balanced Preference Optimization)
- **문제 인식**: DPO가 Rejected 억제에 치중해 전체 품질 하락 현상
- **해법**: 긍정/부정 최적화 **균형 잡기**

#### SimPO (Simple Preference Optimization)
- **핵심**: **참조 모델(Reference Model, DPO에서 KL 제약용으로 쓰는 동결 복사본) 제거**
- **장점**: 타겟 모델 하나만 메모리에 로드 → 메모리/계산 극도 절감
- **권장**: 리소스 극도 제한 환경

#### GRPO (Group Relative Policy Optimization)
- **유명 사용처**: DeepSeek-V3, DeepSeek-R1
- **핵심**: 보상 모델 없이 **그룹 내 상대 비교**로 강화학습
- **강점**: 복잡한 추론(reasoning) 능력 향상에 특히 효과적
- **원리**: 같은 프롬프트에 대한 여러 샘플 그룹 내 상대 순위로 어드밴티지 추정

### 정렬 기법 비교표

| 기법 | 참조 모델 | 보상 모델 | 학습 복잡도 | 추천 상황 |
|---|---|---|---|---|
| **RLHF (PPO)** | 필요 | 필요 | 매우 높음 | 대기업 연구 |
| **DPO** | 필요 | 불필요 | 낮음 | **일반 선호 학습 기본** |
| **ORPO** | 불필요 | 불필요 | 낮음 | SFT+선호를 한 번에 |
| **BPO** | 필요 | 불필요 | 중간 | DPO 품질 보완 |
| **SimPO** | **불필요** | 불필요 | 매우 낮음 | **리소스 최소화** |
| **GRPO** | 선택 | 불필요 | 중간 | **추론 능력 강화** |

## 6. 구조적 최적화 / 신규 접근

### MoE (Mixture of Experts) 파인튜닝
- **정의**: MoE(여러 전문가 서브네트워크 중 입력마다 일부만 활성화하는 구조, Mixtral/DeepSeek 계열)
- **파인튜닝 전략**: 특정 Expert 레이어만 선택적으로 튜닝 → 도메인 지식(의료/법률/금융) 주입에 효과적
- **장점**: 전체 튜닝 대비 파라미터/VRAM 크게 절감

### Knowledge Distillation (지식 증류)
- **개념**: 거대 교사 모델(GPT-4 등)의 추론 과정/확률분포를 작은 학생 모델(Llama 3 8B 등)에 학습
- **결과물**: 체급 대비 매우 강력한 소형 모델
- **대표 예시**: Gemma 2 2B, Phi-3 시리즈

### 다중 모델 앙상블 (PLM + LLM)
- **문제**: 단일 LLM은 확률적 답변에 기반해 분류 정밀도 한계
- **조합**:

| 모델 유형 | 예시 | 역할 |
|---|---|---|
| **PLM** (Pre-trained Language Model, 인코더 기반 분류 특화) | KoELECTRA, KoBERT | "피싱일 확률 X%" 통계적 계산 |
| **LLM** (생성형) | Gemma, Llama | "왜 피싱인지" 논리적 근거 생성 |

- **활용**: 두 점수를 가중 평균 → 오탐지율(False Positive Rate) 감소

## 7. 추론 엔진: vLLM

학습이 끝난 모델을 **프로덕션 서비스**에 올릴 때 단순 `model.generate()`보다 전용 엔진이 몇 배 빠름.

### 핵심 원리: PagedAttention
운영체제의 **가상 메모리(Virtual Memory, 물리 RAM을 페이지 단위로 매핑하는 기법)** 개념을 LLM 추론에 도입.

- **기존 방식 문제**: 문장이 길수록 KV Cache(Attention의 Key/Value 캐시)가 커짐. 엔진이 최대 길이 기준으로 **메모리를 미리 크게 예약** → 실제 사용률 20~40%, 낭비 60~80%
- **vLLM 방식**: KV Cache를 페이지 단위(기본 16 토큰)로 쪼개 **필요한 만큼만 동적 할당** → 남는 공간에 다른 사용자 요청 동시 처리

### 효과

| 지표 | 개선 |
|---|---|
| **처리량(Throughput)** | 동시 응답 사용자 수 2~4배 |
| **비용** | 서버 4대 → 1대 규모 |
| **지연(Latency)** | TTFT(Time To First Token, 첫 토큰 응답까지 걸린 시간) 단축 |

### 사용 방식

vLLM은 내부에 **FastAPI 기반 자체 서버** 내장.

#### ① 자체 API 서버 (간단, 빠른 배포)
```bash
python -m vllm.entrypoints.openai.api_server \
    --model my-model \
    --port 8000
```
OpenAI API 규격(`/v1/chat/completions`, `/v1/completions`) 자동 제공. 외부에 API만 빨리 열고 싶을 때.

#### ② FastAPI와 협력 (커스텀 로직)
KoELECTRA 점수 + Gemma 점수 합산 같은 복합 로직이 필요할 때.

```python
from vllm import LLM, SamplingParams
from fastapi import FastAPI

app = FastAPI()
llm = LLM(model="my-gemma-model")

@app.post("/detect")
async def detect(text: str):
    # 1. KoELECTRA로 점수 계산 (외부 모델)
    electra_score = classify_with_electra(text)
    # 2. vLLM으로 Gemma 추론
    outputs = llm.generate([text], SamplingParams(temperature=0.7))
    gemma_score = parse_score(outputs[0].outputs[0].text)
    # 3. 점수 합산
    return {"final_score": 0.5 * electra_score + 0.5 * gemma_score}
```

흐름: `입력 → KoELECTRA → vLLM(Gemma) → 점수 합산 → 응답`

## 8. 한눈에 보는 SOTA 비교표

| 카테고리 | 기법 | 특징 | 추천 상황 |
|---|---|---|---|
| **효율성** | DoRA | LoRA보다 정교한 가중치 조정 | 고정확도 전문 도메인 |
| **속도/메모리** | Unsloth | 학습 2배↑, 정확도 손실 0% | 실험 반복이 잦을 때 |
| **압축** | QLoRA + NF4 | 4비트 + 어댑터 학습 | 소비자 GPU로 대형 모델 |
| **데이터 효율** | Packing | 패딩 제거, 2~5배 가속 | 짧은 대화 데이터 다수 |
| **정렬(주류)** | DPO | 쌍 데이터 기반, 보상모델 X | 일반 선호 학습 |
| **정렬(통합)** | ORPO | SFT+DPO 동시 | 2단계가 부담될 때 |
| **정렬(초경량)** | SimPO | 참조 모델 제거 | 리소스 극도 제한 |
| **정렬(추론)** | GRPO | 그룹 상대 비교 RL | 복잡한 추론 이행 |
| **도메인 주입** | MoE FT | Expert만 튜닝 | 도메인 특화 지식 |
| **소형화** | Knowledge Distillation | 큰 모델 → 작은 모델 | 체급 대비 성능 극대 |
| **추론(서빙)** | vLLM / PagedAttention | 처리량 2~4배 | 프로덕션 서빙 |
| **배포 포맷** | GGUF | 단일 파일, CPU 추론 가능 | 로컬/엣지 배포 |

## 9. 구현 스니펫 (Unsloth + NF4 + DoRA)

최소 실행 예시. 7~9B 모델을 RTX 4090(24GB) 한 장으로 학습 가능한 설정.

```python
from unsloth import FastLanguageModel
from peft import LoraConfig
from trl import SFTTrainer
from transformers import TrainingArguments
import torch

# 1. 모델 로드 (NF4 양자화)
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="unsloth/gemma-2-9b-bnb-4bit",
    max_seq_length=2048,
    load_in_4bit=True,    # NF4 양자화 활성
    dtype=None,            # 자동 선택 (보통 bfloat16)
)

# 2. LoRA/DoRA 어댑터 부착
model = FastLanguageModel.get_peft_model(
    model,
    r=16,
    lora_alpha=32,
    target_modules=[
        "q_proj", "k_proj", "v_proj", "o_proj",
        "gate_proj", "up_proj", "down_proj",
    ],
    lora_dropout=0.05,
    bias="none",
    use_dora=True,         # DoRA 활성
    use_gradient_checkpointing="unsloth",  # VRAM 절감
    random_state=42,
)

# 3. 학습
trainer = SFTTrainer(
    model=model,
    tokenizer=tokenizer,
    train_dataset=my_dataset,
    dataset_text_field="text",
    max_seq_length=2048,
    packing=True,          # 패딩 제거
    args=TrainingArguments(
        per_device_train_batch_size=2,
        gradient_accumulation_steps=4,
        warmup_steps=10,
        num_train_epochs=3,
        learning_rate=2e-4,
        bf16=True,
        optim="adamw_8bit",
        output_dir="./outputs",
    ),
)
trainer.train()
```

- `load_in_4bit=True` + NF4 = **QLoRA 방식 학습**
- `use_dora=True` = **DoRA로 업그레이드**
- `packing=True` = 짧은 샘플 묶어 배치 효율 극대화
