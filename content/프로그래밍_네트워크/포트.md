# 포트(Port)

> "이미 포트 8000이 사용 중입니다"가 Agent 개발 중 가장 자주 만나는 에러 중 하나다. IP 주소가 건물 주소라면 포트는 그 건물 안의 호실 번호. 개념과 범위, 확인 방법을 정리한다.

관련 문서: [[HTTP_HTTPS]], [[DNS]], [[WebSocket]], [[프록시]]

---

## 1. 포트가 뭔데

**포트(Port, 전송 계층 식별자, 같은 컴퓨터 안에서 어떤 프로그램이 네트워크 패킷을 받을지 구분하는 0 ~ 65535 범위의 번호)** 는 IP 주소만으로는 부족한 "어느 앱?"을 가리는 표지판이다.

포함 관계로 보면:

```
컴퓨터 (IP: 192.168.0.10)
 ├─ 포트 22  → SSH 서버
 ├─ 포트 80  → HTTP 서버
 ├─ 포트 443 → HTTPS 서버
 ├─ 포트 5432 → PostgreSQL
 └─ 포트 8000 → 내가 띄운 FastAPI
```

IP 주소가 아파트 호수까지 적힌 주소라면, 포트는 그 안의 방 번호. 택배 기사가 "202동 1501호"까지만 알면 입구에서 멈추지만, "202동 1501호 안방"까지 알면 바로 꽂아 넣을 수 있다.

---

## 2. IP + 포트 = 소켓

실제 네트워크 연결 하나는 **5-tuple(5요소)** 로 식별된다:

```
(프로토콜, 출발지 IP, 출발지 포트, 목적지 IP, 목적지 포트)
```

- 예: `(TCP, 192.168.0.10, 54321, 104.18.7.192, 443)` → 내 컴퓨터에서 OpenAI API로 HTTPS 접속한 연결

이 (IP:포트) 쌍 하나를 **소켓(Socket, 네트워크 통신의 끝점, OS가 열어주는 파일 비슷한 객체)** 이라 부른다.

---

## 3. 포트 번호 범위

| 범위 | 이름 | 용도 |
|------|------|------|
| 0 ~ 1023 | **Well-known ports** (잘 알려진 포트) | 관례로 정해진 표준 서비스. OS가 root/관리자 권한 필요 |
| 1024 ~ 49151 | **Registered ports** (등록된 포트) | IANA에 등록된 특정 서비스 (예: 8080, 5432, 3306) |
| 49152 ~ 65535 | **Dynamic/Ephemeral ports** (동적/임시 포트) | 클라이언트가 접속할 때 OS가 자동 할당 |

**직접 확인:**

```bash
# Linux: 임시 포트 범위
cat /proc/sys/net/ipv4/ip_local_port_range
# 32768   60999

# Windows (PowerShell)
netsh int ipv4 show dynamicport tcp
```

## 5. TCP 포트 vs UDP 포트

같은 번호라도 **TCP(Transmission Control Protocol, 전송 제어 규약, 연결 기반 순서 보장)** 포트와 **UDP(User Datagram Protocol, 사용자 데이터그램 규약, 비연결 빠른 전송)** 포트는 별개다.

- TCP 53과 UDP 53은 서로 다른 자리
- DNS는 기본 UDP 53, 응답이 크면 TCP 53으로 폴백

| 구분 | TCP | UDP |
|------|-----|-----|
| 연결성 | 3-way handshake 필요 | 없음 |
| 순서 보장 | O | X |
| 속도 | 상대적으로 느림 | 빠름 |
| 주 용도 | HTTP, SSH, DB | DNS, 화상회의, 게임, QUIC |

## 6. 포트 상태 확인하기

### 어떤 포트가 열려 있나

```bash
# Linux/macOS
ss -tulnp            # listen 중인 TCP/UDP
netstat -tulnp       # 오래된 명령, 비슷

# Windows (PowerShell)
netstat -ano | findstr LISTEN
Get-NetTCPConnection -State Listen

# 특정 포트에 무슨 프로세스가 잡고 있나
lsof -i :8000                 # macOS/Linux
netstat -ano | findstr :8000  # Windows → PID 확인 후 tasklist /FI "PID eq 1234"
```

### 원격 포트 열렸는지 확인

```bash
# nc (netcat)
nc -zv api.openai.com 443

# PowerShell
Test-NetConnection api.openai.com -Port 443

# curl로 HTTP 수준 확인
curl -v https://api.openai.com/
```

## 7. "포트 이미 사용 중" 에러 처리

```
OSError: [Errno 48] Address already in use
```

### 원인과 해결

1. **이전 프로세스가 살아있음**
   - `lsof -i :8000`(또는 Windows `netstat -ano | findstr :8000`)으로 PID 확인
   - `kill -9 <PID>`(Linux/macOS) 또는 `taskkill /PID <PID> /F`(Windows)

2. **TIME_WAIT 상태**: TCP 연결 정상 종료 후 OS가 잠깐(60초 정도) 포트 잡고 있음
   - 개발 중엔 다른 포트로 띄우는 게 제일 쉬움
   - 서버 코드에 `SO_REUSEADDR` 옵션 주면 재사용 가능

3. **관리자 권한 필요**: 1023 이하 포트는 root/Administrator만 bind 가능. 개발 서버는 8000번대 쓰자

## 8. 포트 포워딩(Port Forwarding)

### NAT 환경에서

집 공유기 뒤의 서버를 외부에 공개하려면 공유기에서 **포트 포워딩**을 설정. 공유기 외부 포트 80 → 내부 192.168.0.10의 80으로 연결.

### SSH 터널

```bash
# 내 로컬 8080 → 원격 서버의 localhost:5432 (DB 접속용)
ssh -L 8080:localhost:5432 user@remote.com
```

원격 DB가 외부에 포트 열지 않아도 SSH로만 들어가는 사람은 접근 가능. Agent 개발할 때 내부망 서비스에 붙을 때 자주 씀.

### Docker 포트 매핑

```bash
docker run -p 8000:80 nginx
# 호스트의 8000 ← 컨테이너 내부의 80
```

포함 관계:
```
호스트 PC (0.0.0.0:8000)
 └─ Docker 컨테이너 (172.17.0.2:80)
     └─ nginx 프로세스
```

## 9. 방화벽과 포트

방화벽(Firewall)은 포트 단위로 허용/차단한다.

- 회사 방화벽이 443만 열어두면 → HTTP/HTTPS와 WSS는 통과, 일반 DB 포트 5432는 차단
- 이런 이유로 [[WebSocket]]도 포트 443을 그대로 재사용
- 클라우드 Security Group / NSG도 같은 개념

**직접 확인:**

```bash
# Windows 방화벽 규칙
netsh advfirewall firewall show rule name=all | more

# Linux iptables
sudo iptables -L -n
# 또는 ufw
sudo ufw status
```

## 10. 포트와 URL의 관계

URL에 포트를 명시할 수 있다.

```
https://api.example.com:8443/v1/chat
         └──────────────┘ └──┘
         호스트           포트
```

생략하면 스킴 기본값 적용:
- `http://` → 80
- `https://` → 443
- `ws://` → 80
- `wss://` → 443
- `ftp://` → 21

그래서 일반 웹 접속 URL에는 포트가 거의 안 보이는 것.

## 한마디 요약

포트는 한 컴퓨터 안에서 "어느 프로그램이 받을지"를 가리는 0 ~ 65535 번호이고, IP + 포트 조합이 네트워크 통신의 끝점(소켓)이다.
