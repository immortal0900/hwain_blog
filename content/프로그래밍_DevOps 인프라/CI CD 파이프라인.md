**CI/CD 파이프라인**은 한마디로 **"코드를 짜서 실제 사용자에게 도달하기까지의 과정을 자동화한 컨베이어 벨트"**라고 생각하면 됩니다.

개발자가 코드를 작성한 뒤, 그것이 실제 서비스에 반영되기까지는 수많은 반복 작업(빌드, 테스트, 배포 등)이 필요한데, 이것을 **사람이 수동으로 하지 않고 로봇이 자동으로 처리**하도록 만든 시스템입니다.

#### **CI (Continuous Integration, 지속적 통합)**

**"개발자들의 코드를 합치고 잘 돌아가는지 확인하는 단계"**입니다.

- **상황:** 여러 개발자가 각자 맡은 기능을 개발합니다.
    
- **하는 일:**
    
    1. 개발자가 코드를 저장소(Git)에 올립니다.
        
    2. 자동으로 코드를 **빌드**합니다 (실행 가능한 파일로 만듦).
        
    3. 자동으로 **테스트**를 돌립니다 (버그가 없는지, 기존 기능이 안 깨졌는지 확인).
        
- **목적:** "버그를 미리미리 잡자!"
    

#### **CD (Continuous Delivery/Deployment, 지속적 제공/배포)**

**"테스트를 통과한 코드를 실제 사용자에게 전달하는 단계"**입니다.

- **상황:** CI 단계를 무사히 통과했습니다.
    
- **하는 일:**
    
    1. 테스트 서버나 실제 운영 서버에 새 버전을 **업로드**합니다.
        
    2. 서버를 재시작하거나 설정을 적용해서 사용자가 새 기능을 쓸 수 있게 합니다.
        
- **목적:** "빠르고 안전하게 고객에게 업데이트를 제공하자!"


### 파이프라인의 전체 흐름 예시

앞서 작성하신 `NPCClient` 코드를 예로 들어볼까요?

1. **Code (개발):** 당신이 `chat_heroine` 기능을 수정해서 Git에 올립니다(`git push`).
    
2. **Build (빌드):** (CI 도구가 감지) 파이썬 환경을 세팅하고 의존성 라이브러리를 설치합니다.
    
3. **Test (테스트):** "로그인이 잘 되는지", "대화 함수가 에러를 안 뱉는지" 작성해둔 테스트 코드를 자동으로 실행합니다.
    
    - _실패하면?_ -> 당신에게 "테스트 실패했어요!"라고 알림이 오고 배포는 중단됩니다.
        
4. **Deploy (배포):** 테스트를 모두 통과하면, 자동으로 이 코드를 실제 게임 서버에 업데이트합니다.
    

이 **1 -> 2 -> 3 -> 4**의 연결 과정을 **파이프라인**이라고 부릅니다.
