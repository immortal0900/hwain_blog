### **1. LLM Integration (LLM 통합)**

**"우리가 만든 서비스(앱/웹)에 거대 언어 모델(LLM)을 연결하는 행위와 구조"**를 말합니다.

단순히 챗봇을 만드는 것을 넘어, LLM이 우리 서비스의 **데이터베이스**, **외부 API**, **사용자 인터페이스**와 상호작용하도록 만드는 모든 과정을 포함합니다.

#### **주요 구성 요소**

- **모델 연결 (Model Serving):**
    
    - **API 방식:** OpenAI(GPT-4), Anthropic(Claude) 같은 외부 API를 호출하여 사용.
        
    - **로컬 호스팅:** `Ollama`, `vLLM` 등을 사용해 내 서버(GPU)에 Llama 3 같은 모델을 직접 띄워놓고 연결.
        
- **오케스트레이션 (Orchestration):**
    
    - LLM이 혼자서는 못 하는 일을 하게 해주는 도구들입니다. (예: `LangChain`, `LlamaIndex`)
        
    - 사용자의 질문을 분석해서 검색이 필요한지, 계산기가 필요한지 판단하고 연결해 줍니다.
        
- **도구 연결 (Function Calling / Tool Use):**
    
    - LLM에게 "너는 계산기랑 날씨 API를 쓸 수 있어"라고 알려주고, 필요할 때 함수를 실행하게 만드는 것입니다. (사용자님이 관심 있어 하신 `MCP`도 여기에 해당합니다.)

### **2. Inference Pipeline (추론 파이프라인)**

**"사용자가 질문을 입력하고(Input), 최종 답변(Output)을 받기까지 데이터가 흐르는 일련의 처리 과정"**입니다.

LLM은 텍스트를 그대로 이해하지 못하기 때문에, 숫자로 바꾸고 계산한 뒤 다시 텍스트로 바꾸는 과정이 필요합니다. 이 전체 흐름을 파이프라인이라고 합니다.

#### **파이프라인의 4단계 (End-to-End)**

1. **전처리 (Pre-processing / Tokenization):**
    
    - 사용자의 질문("안녕?")을 모델이 이해할 수 있는 숫자(토큰 ID)로 변환합니다.
        
    - 프롬프트 엔지니어링 템플릿을 입히는 과정도 여기에 포함됩니다. (예: "너는 친절한 AI야" + "안녕?")
        
2. **검색 및 컨텍스트 주입 (Retrieval - RAG 사용 시):**
    
    - (선택 사항) 질문과 관련된 데이터를 벡터 DB에서 찾아와 프롬프트에 끼워 넣습니다.
        
3. **모델 추론 (Model Inference):**
    
    - **가장 무거운 단계**입니다. GPU가 열심히 행렬 연산을 수행하여 다음 토큰(글자)을 확률적으로 예측합니다.
        
    - 이때 `KV Cache` 같은 기술을 써서 속도를 높입니다.
        
4. **후처리 (Post-processing / Detokenization):**
    
    - 모델이 뱉어낸 숫자들을 다시 사람이 읽을 수 있는 글자로 바꿉니다.
        
    - 욕설 필터링, 포맷팅(JSON 변환) 등의 마무리 작업이 수행됩니다.
