# 환경변수

> API 키를 실수로 깃허브에 올린 적 있어서 `.env` 관리를 제대로 공부하게 됐고, 그 과정에서 환경변수가 뭔지 OS 레벨에서 다시 정리함.

## 한 줄 요약
**환경변수(Environment Variable)는 OS가 프로세스를 띄울 때 같이 들려 보내는 key=value 형태의 설정 메모다.** 내 코드에 하드코딩 안 하고 외부에서 주입할 수 있게 해주는 OS의 공식 전달 통로.

## 용어부터

- **환경변수(Environment Variable, 프로세스 실행 시 OS가 제공하는 key=value 문자열 목록)**: 예) `PATH=/usr/bin:/usr/local/bin`, `OPENAI_API_KEY=sk-...`
- **PATH(전역 실행 경로, OS가 명령어 입력 시 뒤지는 폴더 목록)**: 가장 대표적인 환경변수. `python` 쳤을 때 어디 폴더부터 찾을지 순서대로 나열된 것.
- **셸(Shell, 사용자 명령어를 받아 해석·실행해주는 프로그램)**: bash, zsh, PowerShell, cmd 등. 환경변수를 자식 프로세스에게 넘겨주는 주체.
- **자식 프로세스(Child Process, 부모가 띄운 하위 [[프로세스 vs 스레드|프로세스]])**: 환경변수를 **부모로부터 복사**해서 시작함.
- **`.env` 파일(프로젝트별 환경변수 모음집, OS 표준 아니고 앱 관례)**: `python-dotenv` 같은 라이브러리가 읽어서 프로세스 환경으로 주입.

## 포함 관계: 환경변수 계층

```
OS 전역 (시스템 환경변수)
 └── 로그인 사용자 (유저 환경변수)
      └── 셸 세션 (쉘 시작 시 ~/.bashrc, ~/.zshrc에서 로드)
           └── 내가 띄운 프로세스 (셸에서 export한 변수 상속)
                └── 그 프로세스의 자식 (부모 환경 복사)
```

**핵심**: 환경변수는 **아래로만 전달**된다. 자식 프로세스가 환경변수 바꿔도 부모에는 영향 없음. 이게 `export API_KEY=xxx` 하고 쉘 닫으면 사라지는 이유.

## 범위별 환경변수 비교표

| 범위 | 어디에 저장 (Windows) | 어디에 저장 (Linux/macOS) | 영향 범위 | 반영 시점 |
|---|---|---|---|---|
| **시스템** | 레지스트리 `HKLM\...\Environment` | `/etc/environment`, `/etc/profile` | 모든 사용자, 모든 프로세스 | OS 재시작 또는 새 세션 |
| **사용자** | 레지스트리 `HKCU\Environment` | `~/.bashrc`, `~/.zshrc`, `~/.profile` | 해당 사용자 모든 새 셸 | 새 터미널 열기 |
| **셸 세션** | 현재 PowerShell/cmd | 현재 bash/zsh | 이 터미널 + 여기서 띄운 자식 | 즉시 |
| **프로세스** | 실행 시 `-e` 옵션이나 코드 | 실행 시 `KEY=VAL cmd` | 그 프로세스 한정 | 즉시 |

**AI 개발에서 주로 쓰는 범위**: `.env` → 프로세스 범위 주입이 표준. 실수로 시스템 전역에 `API_KEY` 박아놓으면 다른 프로젝트에도 노출됨.

## PATH 구조 뜯어보기

PATH는 **여러 경로를 구분자로 이은 문자열** 하나일 뿐이다.

### Windows
```
C:\Windows\System32;C:\Windows;C:\Python313\Scripts;C:\Users\me\.local\bin
```
구분자: `;` (세미콜론)

### Linux/macOS
```
/usr/local/bin:/usr/bin:/bin:/home/me/.local/bin
```
구분자: `:` (콜론)

**동작 원리**: 터미널에 `python` 입력하면 OS가 PATH 왼쪽부터 순서대로 폴더를 뒤져서 `python.exe`(Windows) 또는 `python`(Linux)을 찾아 실행. 먼저 발견한 것을 씀. pyenv 같은 버전 매니저가 PATH 앞쪽에 끼어들어 우선순위를 조작하는 방식.

## 일상 비유

- **환경변수 = 출근 시 회사 사무실에 붙어있는 포스트잇**: "커피머신 비밀번호: 1234", "와이파이: guest". 사원이 들어오면 이미 붙어있고, 필요하면 자기 자리에도 베껴다 붙임(프로세스가 환경변수 상속).
- **PATH = 전화번호부 순서**: "요리사 부르려면 여기 먼저, 없으면 다음 집, 또 없으면 그 다음" 순으로 탐색.
- **`.env` = 프로젝트별 전용 포스트잇**: 회사 공용이 아니라 이 방 안에서만 붙여 쓰는 것.

## 단계 분해: 프로세스 실행 시 환경변수가 전달되는 흐름

Windows PowerShell에서 `python agent.py` 실행 시:

1. PowerShell이 자체 환경변수 테이블 보유 (OS 로그인 시 사용자·시스템 변수 머지해서 로드)
2. `python` 명령어 → PATH 뒤져서 `C:\Python313\python.exe` 찾음
3. Windows에 `CreateProcess` 시스템 콜 요청, **현재 환경변수 블록을 통째로 복사해서 전달**
4. 새로 뜬 python.exe가 그 환경변수를 받아 자체 메모리에 보관
5. `os.environ`으로 접근 가능
6. python이 다시 자식 프로세스 띄우면(`subprocess.run`) 그 환경을 또 복사해서 넘김

**포인트**: 2단계에서 셸이 복사본을 보내는 거라, 자식이 환경변수 바꿔도 셸의 환경은 안 바뀜. `subprocess`로 `export X=1` 해봐야 파이썬 돌아와서 `os.environ`에 X 없는 이유.

## 설정 방법 정리

### Windows

#### PowerShell (현재 세션만)
```powershell
$env:OPENAI_API_KEY = "sk-..."
```

#### 영구 설정 (사용자 범위)
```powershell
[Environment]::SetEnvironmentVariable("OPENAI_API_KEY", "sk-...", "User")
# 새 터미널 열어야 반영
```

#### GUI
`시스템 속성` → `환경 변수` → `사용자 변수` 또는 `시스템 변수`

### Linux/macOS

#### 현재 셸만
```bash
export OPENAI_API_KEY="sk-..."
```

#### 영구 설정
```bash
echo 'export OPENAI_API_KEY="sk-..."' >> ~/.bashrc
source ~/.bashrc
```

#### 한 명령만 적용
```bash
OPENAI_API_KEY="sk-..." python agent.py
# 이 python 프로세스에만 유효
```

## 파이썬에서 다루기

### 읽기
```python
import os

api_key = os.environ["OPENAI_API_KEY"]       # 없으면 KeyError
api_key = os.environ.get("OPENAI_API_KEY")   # 없으면 None
api_key = os.getenv("OPENAI_API_KEY", "default")
```

### 쓰기 (현재 프로세스 한정)
```python
os.environ["DEBUG"] = "1"
# 이 파이썬 프로세스 + 여기서 띄우는 자식에게만 유효
# 부모 셸에는 영향 없음
```

### `.env` 파일 로드
```python
# pip install python-dotenv
from dotenv import load_dotenv
load_dotenv()   # ./.env 파일 읽어서 os.environ에 주입
```

`.env` 파일 예시:
```
OPENAI_API_KEY=sk-...
ANTHROPIC_API_KEY=sk-ant-...
LANGFUSE_HOST=https://cloud.langfuse.com
LOG_LEVEL=DEBUG
```

## 직접 확인해 보기

### Windows
```powershell
# 전체 환경변수 보기
Get-ChildItem Env:

# 특정 변수
$env:PATH
$env:PATH -split ';'   # 한 줄씩 끊어서

# 현재 프로세스 환경변수 개수
(Get-ChildItem Env:).Count
# 보통 40~60개
```

### Linux/macOS
```bash
env                    # 전부 출력
printenv PATH          # 하나만
echo $PATH | tr ':' '\n'   # 줄 단위로

# 특정 프로세스의 환경변수 엿보기
cat /proc/<PID>/environ | tr '\0' '\n'
```

### 파이썬
```python
import os
for k, v in sorted(os.environ.items()):
    print(f"{k}={v[:30]}...")   # 값 앞 30자만
print(f"\n총 {len(os.environ)}개")
```

## AI Agent 개발에서 환경변수 쓰는 이유

| 목적 | 예시 | 대안 대비 장점 |
|---|---|---|
| **비밀 키 분리** | `OPENAI_API_KEY`, `DB_PASSWORD` | 코드에 안 박아서 git 유출 방지 |
| **환경별 설정** | `ENV=prod` vs `ENV=dev` | 같은 코드로 개발/운영 동시 지원 |
| **동적 튜닝** | `LOG_LEVEL=DEBUG`, `MODEL=opus-4-7` | 재배포 없이 행동 변경 |
| **Docker 호환** | `docker run -e KEY=val` | 컨테이너 표준 방식 |
| **12-Factor App 원칙** | 설정은 환경에서 읽기 | 업계 베스트 프랙티스 |

## 보안 주의점 (AI Agent에서 특히 중요)

1. **`.env`는 `.gitignore`에 반드시 등록**
   ```
   # .gitignore
   .env
   .env.local
   .env.*.local
   ```

2. **로그에 환경변수 덤프 금지**
   ```python
   # 절대 금지
   logger.debug(f"env: {os.environ}")
   # API 키가 통째로 로그에 찍힘
   ```

3. **`.env.example`은 커밋해도 OK** (값 비워둔 템플릿)
   ```
   OPENAI_API_KEY=
   ANTHROPIC_API_KEY=
   ```

4. **자식 프로세스 띄울 때 환경 필터링**
   ```python
   import subprocess
   # 안전한 환경만 골라서 전달
   safe_env = {"PATH": os.environ["PATH"], "HOME": os.environ["HOME"]}
   subprocess.run(["some_tool"], env=safe_env)
   ```
   안 그러면 툴이 내 `OPENAI_API_KEY`를 외부로 유출할 수도 있음.

5. **프로덕션**: `.env` 파일보다 **시크릿 매니저**(AWS Secrets Manager, Vault, Doppler) 추천. 파일은 서버 침투되면 바로 노출.

## 환경변수의 한계와 대안

| 한계 | 설명 | 대안 |
|---|---|---|
| 문자열만 가능 | `int`, `list` 직접 못 넣음 | JSON 직렬화 or pydantic-settings |
| 계층 구조 약함 | `A.B.C` 같은 중첩 표현 번거로움 | YAML/TOML 설정 파일 |
| 값 크기 제한 | OS마다 다르지만 Windows는 블록 32KB 한계 | 파일 경로만 넘기고 파일에서 읽기 |
| 변경 실시간 반영 안 됨 | 프로세스 시작 시점 기준 고정 | 설정 파일 + 파일 감시 |

## 왜 이렇게 설계했나

- **프로세스 격리 유지**: 각 프로세스가 자기 환경변수 사본을 가지므로 서로 영향 안 줌. [[프로세스 vs 스레드|프로세스]]의 메모리 격리 원칙과 일관.
- **언어·플랫폼 중립**: OS가 제공하는 메커니즘이라 파이썬이든 Go든 Rust든 동일하게 접근 가능.
- **설정 외부화(Configuration Externalization) 원칙**: 코드와 설정을 분리하면 재빌드 없이 동작 변경, 같은 이미지로 여러 환경 배포 가능.

## 한마디 요약
**환경변수는 OS가 공식으로 제공하는 key=value 주입 통로. 비밀은 `.env`에 담고 git엔 절대 올리지 말기. 프로덕션은 시크릿 매니저로 한 단계 업그레이드.**
