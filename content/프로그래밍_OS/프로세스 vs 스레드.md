# 프로세스 vs 스레드

> AI Agent 짤 때 멀티 에이전트를 "프로세스로 띄울지 스레드로 띄울지" 고민이 자주 생겨서 기초부터 다시 정리함.

## 한 줄 요약
**프로세스(Process)는 독립된 집 한 채, 스레드(Thread)는 그 집 안에 사는 식구들이다.** 집을 하나 더 짓는 건 비싸지만 안전하고, 식구를 늘리는 건 싸지만 서로 물건을 공유해서 사고가 나기 쉽다.

## 핵심 용어부터 풀이
- **프로세스(Process, 실행 중인 프로그램의 인스턴스, OS가 자원을 할당하는 단위)**: `python agent.py`를 실행하면 OS가 메모리/파일핸들/네트워크 소켓을 묶어 하나의 덩어리로 배정한 것. PID(Process ID, 프로세스 고유 번호)가 붙음.
- **스레드(Thread, 프로세스 안에서 실제 CPU가 실행하는 작업 흐름)**: 한 프로세스 안에서 동시에 여러 일을 처리하려고 쪼갠 실행 단위. TID(Thread ID)가 붙고, 같은 프로세스의 스레드끼리는 메모리를 공유함.
- **컨텍스트 스위칭(Context Switching, 문맥 교환)**: CPU가 A 작업 하다가 B 작업으로 넘어갈 때 A의 레지스터 값/프로그램 카운터를 저장했다 다시 복원하는 행위. 프로세스 간 스위칭이 훨씬 비쌈.

## 포함 관계

```
OS
 └── 프로세스 (독립된 주소 공간 1개 보유)
      ├── 스레드 1 (주소 공간 공유)
      ├── 스레드 2
      └── 스레드 N (최소 1개 이상, "메인 스레드"라고 부름)
```

**한 프로세스는 반드시 1개 이상의 스레드를 가진다.** 스레드 0개인 프로세스는 없음. 파이썬 스크립트 실행해도 내부적으로 "메인 스레드"라는 게 돌아가고 있는 것.

## 나란히 비교표

| 관점 | 프로세스 | 스레드 |
|---|---|---|
| **무엇** | 실행 중인 프로그램 전체 | 프로세스 안 실행 흐름 |
| **어디에** | OS 커널이 관리 | 해당 프로세스 내부 |
| **메모리** | 독립된 가상 주소 공간 보유 | 같은 주소 공간 공유 (Heap/Data 공유, Stack만 개별) |
| **생성 비용** | 비쌈 (수 ms, 메모리 수 MB~수십 MB) | 쌈 (수 μs, 스택용 메모리 1~8 MB만) |
| **통신 방법** | IPC 필요 (파이프, 소켓, 공유 메모리, 큐) | 변수 직접 공유 (락 필요) |
| **충돌 시 영향** | 프로세스 하나만 죽음 | 스레드 하나가 세그폴트 내면 프로세스 전체 죽음 |
| **보안 격리** | 강함 (OS가 메모리 보호) | 없음 (같은 집 식구) |
| **Python GIL 영향** | 없음 (프로세스마다 GIL 따로) | 있음 (같은 프로세스 내 파이썬 바이트코드 동시 실행 불가) |

## 일상 비유
- **프로세스 = 아파트 한 채**: 현관문 잠겨있고, 옆집에서 내 냉장고 물건 못 꺼냄. 이사(생성) 비쌈.
- **스레드 = 한 집 식구들**: 냉장고(Heap) 공유, 하지만 각자 책상(Stack)은 따로. 식구 한 명이 가스불 안 잠그고 나가면(세그폴트) 집 전체가 불남.

## 메모리 구조 관점에서 무슨 차이냐

프로세스 하나의 [[메모리 구조]]는 Code / Data / Heap / Stack 네 영역으로 나뉘는데,

- **프로세스 간 분리**: Code/Data/Heap/Stack 전부 독립. A 프로세스의 `x = 10`은 B 프로세스에서 절대 못 봄.
- **스레드 간 공유**: Code/Data/Heap은 **공유**, Stack만 **스레드마다 1개씩**. 그래서 스레드 A가 전역 변수 건드리면 스레드 B가 바로 영향받음 → **동기화(lock, semaphore) 필요**.

## 단계 분해: 파이썬에서 `multiprocessing`과 `threading` 돌려보기

### 1단계: 프로세스 2개 띄우기
```python
from multiprocessing import Process
import os

def work():
    print(f"PID={os.getpid()}")  # 새로 찍힘

if __name__ == "__main__":
    p1 = Process(target=work); p1.start()
    p2 = Process(target=work); p2.start()
    p1.join(); p2.join()
```
실행하면 PID 2개가 서로 다르게 찍힘. 각각 독립된 파이썬 인터프리터가 뜸.

### 2단계: 스레드 2개 띄우기
```python
from threading import Thread
import os, threading

def work():
    print(f"PID={os.getpid()}, TID={threading.get_ident()}")

t1 = Thread(target=work); t1.start()
t2 = Thread(target=work); t2.start()
t1.join(); t2.join()
```
PID는 **같고** TID만 다름. 인터프리터는 1개만 뜸.

## 직접 확인해 볼 방법

### Windows
```powershell
# 현재 프로세스 목록 (PID, 이름, 사용 메모리)
Get-Process | Select-Object Id, ProcessName, WS | Sort-Object WS -Descending | Select-Object -First 10

# 특정 프로세스의 스레드 개수
Get-Process python | Select-Object Id, Threads
# Threads 필드 크기가 스레드 수. 예: 파이썬 기본 실행해도 3~5개 떠있음 (GC, 시그널 핸들러 등)
```

### Linux/WSL
```bash
ps -eLf | grep python   # -L 붙이면 스레드까지 보여줌. LWP 열이 TID
cat /proc/<PID>/status | grep Threads
```

## AI Agent 개발 관점에서 언제 뭘 쓰나

| 상황 | 선택 | 이유 |
|---|---|---|
| LLM API 호출 여러 개 병렬 (I/O 대기) | **스레드** or [[동시성과 async-await\|async]] | 대부분 시간이 네트워크 대기라 GIL 영향 적음 |
| 임베딩 계산 / 로컬 모델 추론 (CPU 바운드) | **프로세스** (`multiprocessing`) | 파이썬 GIL 때문에 스레드 여러 개 띄워도 CPU 한 코어만 씀 |
| 각 에이전트가 완전 독립 (크래시 격리 필요) | **프로세스** | 한 에이전트 죽어도 전체 시스템 살아있음 |
| Tool 실행이 짧고 빈번 | **스레드** | 생성 비용 수 μs, 프로세스는 수 ms라 오버헤드 큼 |

## 왜 이렇게 설계했나

- **프로세스 격리**: 초창기 OS가 "한 앱이 죽으면 다른 앱도 같이 죽는" 문제를 풀려고 만든 것. 가상 메모리로 주소 공간을 분리해서 "옆 프로세스 메모리 절대 못 건드리게" 강제함. 대가는 IPC 오버헤드.
- **스레드 도입**: 프로세스가 너무 비싸서 "한 앱 안에서만이라도 싸게 병렬 처리하자"고 나온 것. 메모리 공유가 공짜라 빠르지만, 대가로 race condition(경쟁 조건) 위험을 프로그래머가 짊어짐.

## 자주 헷갈리는 포인트

- **"스레드가 프로세스보다 빠르다"는 반쪽 진실**: 생성/컨텍스트 스위칭이 빠른 거지, 실행 속도가 빠른 건 아님. 파이썬은 GIL 때문에 CPU 바운드 작업에서 스레드가 오히려 느릴 수도 있음.
- **파이썬 `asyncio`는 스레드도 프로세스도 아님**: 단일 스레드 안에서 이벤트 루프로 돌리는 **협력적 동시성**. [[동시성과 async-await]]에서 따로 정리.

## 한마디 요약
**격리·안정성이 필요하면 프로세스, 속도·메모리 효율이 필요하면 스레드. 파이썬 AI 에이전트는 I/O면 async, CPU면 multiprocessing이 정석.**
