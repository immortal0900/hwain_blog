**1단계 — 후보 검색 (LLM 아님):** 새 엣지가 추출되면, semantic 유사도 + BM25 + 그래프 순회로 기존 엣지 중 충돌 가능성이 있는 후보를 가져와. 이건 인덱스 기반이라 빠르고 LLM 호출 안 해.

**2단계 — 모순 판단 (LLM):** 시스템은 LLM을 사용해서 새 엣지를 의미적으로 유사한 기존 엣지들과 비교하고, 잠재적 모순을 식별한다. 시간적으로 겹치는 모순이 발견되면, 기존 엣지의 t_invalid를 무효화하는 엣지의 t_valid 시간으로 설정한다.

새 엣지마다 invalidation prompt(무효화 프롬프트)를 사용해서 LLM 호출을 하고, 기존의 유사 엣지들을 컨텍스트로 제공한다.

```
기존 엣지: (화인)-[:WORKS_AT]->(A회사)  t_valid=2023-01, t_invalid=null (현재 유효)

새 엣지:   (화인)-[:WORKS_AT]->(B회사)  t_valid=2024-06
```

LLM이 "이 두 개 모순이다" 판단하면:

```
기존 엣지: (화인)-[:WORKS_AT]->(A회사)  t_valid=2023-01, t_invalid=2024-06  ← 여기가 바뀜
새 엣지:   (화인)-[:WORKS_AT]->(B회사)  t_valid=2024-06, t_invalid=null
```

**기존 엣지의 t_invalid = 새 엣지의 t_valid로 채운다**는 뜻이야. "새 사실이 유효해지는 시점 = 옛 사실이 무효화되는 시점"이니까.

삭제하는 게 아니라 "2023-01부터 2024-06까지는 A회사가 맞았다"는 이력이 남는 거지.
벡터 검색 자체가 top-k 기반이라 내부적으로 k개만 가져와. 정확한 k 값은 설정에 따라 다르지만, 보통 이런 후보 검색에서는 10~20개
**hreshold로 최소 유사도를 거르고, top-k로 개수를 제한하는** 이중 필터
