## 검색 시스템의 3단계

```
1단계: 토큰화     → 텍스트를 쪼갬
2단계: 인덱싱     → 역인덱스(토큰 → 문서 매핑표) 구축
3단계: 스코어링   → 검색 결과에 점수 매기기
```

**PGroonga**는 1~3단계를 **전부 포함하는 검색 엔진 확장**입니다:

- 1단계: N-gram으로 토큰화
- 2단계: Groonga 엔진으로 역인덱스 구축
- 3단계: TF로 점수 

**BM25**는 **3단계(스코어링)만** 가리킵니다. 역인덱스에서 후보를 찾은 뒤 "이 문서가 얼마나 관련 있는지" 점수를 매기는 알고리즘일 뿐입니다.

## 다른 시스템들도 같은 구조

|검색 시스템 (식당)|토큰화 (재료 손질)|인덱싱 (냉장고 정리)|스코어링 (레시피)|
|---|---|---|---|
|**PGroonga**|N-gram|Groonga 역인덱스|TF|
|**Elasticsearch**|형태소 분석 (nori 등)|Lucene 역인덱스|**BM25**|
|**pg_search (ParadeDB)**|설정 가능|Tantivy 역인덱스|**BM25**|
|**LanceDB FTS**|설정 가능|Tantivy 역인덱스|**BM25**|
## 데이터 저장 시 인덱싱 방식: 역색인 (Inverted Index)

키워드 검색 엔진은 데이터를 저장할 때 단순히 텍스트를 쌓아두는 것이 아니라, 책 뒷면의 '찾아보기'와 같은 **역색인** 구조를 생성합니다.

### 역색인 생성 과정 및 변수 정의

1. **토큰화 (Tokenization):** 문장을 단어 단위(토큰)로 쪼갭니다.
    
2. **정규화 (Normalization):** 대소문자 통합, 어근 추출(Stemming), 불용어(Stopwords) 제거 등을 수행합니다.
    
3. **역색인 매핑:** 각 단어가 어떤 문서(Document ID)의 어느 위치에 등장하는지 기록합니다.
    

Python

```python
# docs: 원본 문서 데이터 세트 (검색 대상이 되는 전체 텍스트)
# inverted_index: 단어를 키(Key)로, 문서 ID 목록을 값(Value)으로 갖는 구조
# word: 추출된 개별 키워드

docs = {
    1: "AI is powerful",
    2: "AI agents are future"
}

# 인덱싱 결과 예시 (내부 저장소에 기록됨)
inverted_index = {
    "AI": [1, 2],       # 'AI' 단어는 문서 1, 2에 있음
    "powerful": [1],   # 'powerful'은 문서 1에만 있음
    "future": [2]      # 'future'는 문서 2에만 있음 (나중에 검색 속도를 높임)
}
```

**STEP 1 — 토큰화 (문서를 쪼개기)**

N-gram 방식으로 텍스트를 쪼갭니다. 예를 들어 bigram(2글자씩)이면:

"주택담보대출" → "주택", "택담", "담보", "보대", "대출"

**STEP 2 — 역인덱스 구축 (토큰 → 문서 매핑표 만들기)**

Elasticsearch와 마찬가지로 **역인덱스**를 만듭니다. "이 토큰이 어떤 문서에 있는지"를 기록하는 표입니다:

```
"주택" → [문서1(위치:0), 문서3(위치:42), 문서7(위치:15)]
"택담" → [문서1(위치:1), 문서3(위치:43)]
"담보" → [문서1(위치:2), 문서3(위치:44), 문서7(위치:16)]
"보대" → [문서1(위치:3), 문서3(위치:45)]
"대출" → [문서1(위치:4), 문서3(위치:46), 문서5(위치:8)]
```

위치(position) 정보까지 저장하기 때문에 "주택담보대출"이라는 연속된 구문도 찾을 수 있습니다.
