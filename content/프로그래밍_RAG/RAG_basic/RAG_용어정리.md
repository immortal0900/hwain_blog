## 임베딩 #RAG/임베딩 
- 임베딩은 **BERT, GPT, Word2Vec, ResNet** 같은 딥러NING 모델이 텍스트나 이미지의 의미를 추출하여 고차원 벡터로 변환하는 과정
- 문서의 임베딩과 질문의 임베딩은 같은 모델로 이루어져야 함
- 헷갈리는 부분: FAISS는 이렇게 **생성된 결과물(임베딩 벡터)을 입력으로 받을 뿐**, 임베딩을 만들지는 않습니다.

## #RAG/FAISS
- FAISS는 데이터베이스가 아니다.
- 고차원 벡터들을 메모리(RAM)에 올리고, 이 벡터들 간의 유사도를 매우 빠르게 검색하는 기능
- 데이터를 임베딩 벡터로 만들어 FAISS에 
- 인덱싱 과정을 거쳐 생성된 구조화된 데이터 덩어리, 즉 Index 객체(ex. faiss.write_index)가 FAISS 저장소의 실체임 
- 벡터를 구조화 하는 전략: 
	- 클러스터링: 비슷한 벡터끼리 미리 그룹으로 묶어서 그 안에서만 상세 검색해서 진행 속도를 높인다
	- 양자화: 벡터 데이터를 압축하여 더 적은 메모리를 사용하도록 만들어 속도를 향상
	- 파티셔닝: 검색시 쿼리 벡터가 속한 구역과 그 주변의 몇개 구역만 탐색하여 검색 범죄를 좁힘
- LangChain과 같은 프레임워크에서 FAISS를 Vector Store(벡터 저장소)라고 부르는 것은, 이러한 '검색을 위한 벡터 인덱스 저장'이라는 특화된 역할을 가리키는 것
- 유클리드거리(L2거리)와 내적 계산에 특화됨
	- 유클리드거리(L2거리): 지도 위의 두 점 사이의 직선거리를 잼(벡터의 크기와 방향을 모두 고려)
	- 내적: 두 벡터가 얼마나 같은 방향을 보고 있는지 측정. 두 벡터의 크기와 코사인 값을 곱한 결과 
### 리트리버와 FAISS 동작 방식
**설명**: 리트리버는 대규모 데이터베이스에서 사용자의 질문(쿼리)과 가장 관련성이 높은 정보를 찾아내는 시스템을 말합니다.

1. **저장 (Indexing)**: 미리 수많은 문서나 데이터를 임베딩 벡터로 만들어 FAISS에 저장해 둡니다. FAISS는 이 벡터들을 검색하기 쉬운 구조(인덱스)로 만들어 관리합니다.
2. **검색 (Search)**: 사용자의 질문이 들어오면, 이 질문 역시 동일한 임베딩 모델을 통해 벡터로 변환됩니다.
3. **유사도 비교**: FAISS는 이 질문 벡터와 미리 저장해 둔 수많은 벡터들 사이의 유사도를 매우 빠르게 계산하여, 가장 가까운(가장 관련성 높은) 벡터들을 순식간에 찾아냅니다.

## #코사인유사도
- 벡터의 크기는 무시하고 오직 방향성의 유사도를 파악하는 방법
- **코사인 유사도** = `정규화된 벡터 A`와 `정규화된 벡터 B`의 **내적**

## #RAG/VectorDB
- VectorDB는 텍스트, 이미지, 오디오와 같은 데이터를 벡터(숫자의 배열) 형태로 저장하고, 특정 벡터와 의미적으로 가장 유사한 벡터를 신속하게 검색하는 데 최적화된 데이터베이스
### VectorDB 필요 이유
- 최신 정보 반영
- 환각 현상 감소
- 비용 및 효율성
- 전문분야 적용
### VectorDB와 일반 DB의 차이점
일반 DB가 정해진 규칙에 따라 데이터를 정확하게 찾아내는 데 강점이 있다면, VectorDB는 데이터의 '의미'를 이해하고 그 의미를 기반으로 가장 관련성 높은 데이터를 빠르고 유연하게 찾아내는 데 특화됨
RAG(검색 증강 생성)에서 VectorDB는 **LLM(거대 언어 모델)의 외부 기억 장치** 역할을 하는 특수한 데이터베이스입니다. LLM이 더 정확하고 최신 정보를 바탕으로 답변을 생성할 수 있도록, 질문과 관련된 정보를 매우 빠르게 찾아 제공하는 것이 핵심 기능입니다.

|구분|**Vector DB (벡터 데이터베이스)**|**일반 DB (관계형 데이터베이스)**|
|---|---|---|
|**데이터 형태**|**비정형 데이터** (텍스트, 이미지 등)를 의미적으로 변환한 **고차원 벡터(Vector)**를 저장합니다.|**정형 데이터**를 **테이블(Table)**의 행(Row)과 열(Column) 구조로 저장합니다.|
|**주요 검색 방식**|**유사도 검색 (Similarity Search):** '의미적으로 얼마나 가까운가?'를 기준으로 데이터를 찾습니다. (예: '고양이'와 유사한 이미지 검색)|**정확한 일치 검색 (Exact Match):** '특정 조건에 맞는가?'를 기준으로 데이터를 찾습니다. (예: 이름이 '홍길동'인 사용자 검색)|
|**핵심 기술**|**근사 최근접 이웃(ANN)** 알고리즘을 사용하여 수억 개의 데이터 중에서도 유사한 데이터를 빠르게 찾습니다.|**SQL(Structured Query Language)**을 사용하여 정해진 규칙에 따라 데이터를 조회, 추가, 수정, 삭제합니다.|
|**주요 사용 사례**|- AI 챗봇, RAG 시스템 - 이미지/음성 검색 - 추천 시스템 - 이상 탐지|- 고객 정보 관리 - 재고 관리 - 금융 거래 기록 - 웹사이트 회원 시스템|
|**예시**|'AI 기술의 미래'라는 문장과 **가장 비슷한 의미를 가진** 다른 문서를 찾아줘.|'2024년'에 작성된 'AI' 카테고리의 모든 게시글을 찾아줘.|
